## [0.6.0] - 2026-11-18

### Added

- **Native browser login and one-origin Console (plan 69 slice 2)** — Add opt-in password, OIDC and signed-proxy login with revocable cookies, CSRF checks, shared throttling and first-admin setup. Password mode is development-only; OIDC uses PKCE, nonce verification and one-time browser-bound attempts. Human-admin cookie-only member and service-account management protects the last active human admin and preserves removed identities. A cookie-only resource proxy enforces existing role floors and withdraws streams within 15 seconds. Private browser responses forbid caching. Native proxy-asserted browser mutations check exact Origin. Setup and cookie key issuance fence authority; password login records activity and cancels queued hashing. Chart-managed key rotation rolls legacy Console. Gateway admin cookies use current roles and CSRF for writes; offered legacy credentials keep precedence. Public `/v1` and gateway inference never accept cookies; existing legacy lanes remain available. Compose and Helm can deploy the independently published Console behind a digest-pinned Caddy edge in explicit native mode. Legacy BFF routing, escaped alias names and separate SDK listeners remain available. Native Casdoor callbacks terminate at the control plane, which alone receives the RP client secret. Defaults and the separately managed staging Console stay unchanged. This slice adds no root-key ownership, playground access or delegation credentials. No release until plan 69 slice 7.

- **MCP servers that host only the deprecated HTTP+SSE transport are reachable** ([#348](https://github.com/OpenSDLC-Dev/managed-agent-platform/issues/348)) — the reference documents an automatic fallback for such servers, and this platform now takes it. The MCP client still tries Streamable HTTP first. When the latest POST is answered 400, 404 or 405, its body is at most 64 KiB and not a JSON-RPC error, and no earlier POST succeeded, the client opens the server URL as a 2024-11-05 SSE stream and runs the connection over it. One stream carries every answer, so the per-request cap bounds the whole connection: 30 seconds for tool discovery, two minutes for a tool call. A stream that names a message endpoint on another origin fails the connection. When both transports fail, the error names both attempts. [docs/DIVERGENCES.md](../../docs/DIVERGENCES.md) records the one recorded difference this platform keeps by choice: every connection tries Streamable HTTP first, with no memory of an earlier fallback.

- **Once-ever first-admin setup (plan 69 slice 1)** — With identity enabled and no admin-granting map, a never-bootstrapped install delivers a one-hour setup code per control-plane replica. Each code is stored only by hash in the database and delivered in an exclusive `0600` file inside a fresh `0700` temporary directory. Logs show only the path and expiry, never the code. Delivery failure stops startup; orderly return removes that process's file and directory. Same-UID, root and other file readers remain privileged: retrieve the code privately and redeem it promptly through the signed-in identity lane. Redeeming one spends every replica's code. Enabling an admin-granting map invalidates old codes at startup; replicas using that map also refuse redemption. Any first admin grant closes setup permanently, including a mapped admin; later demotion never reopens it. Invalid or expired codes and malformed request bodies no longer queue setup locks that block unrelated sign-ins. [The security guide](../../docs/self-hosted-security.md#9-single-sign-on-and-the-bundled-identity-provider) covers retrieval, crash leftovers and SQL recovery. Member APIs, cookies, passwords and owned keys are not part of this slice.

- **Plan 69 approved — principal-bound authentication** ([#997](https://github.com/OpenSDLC-Dev/managed-agent-platform/pull/997), [docs/plan/69_principal-bound-auth.md](../plan/69_principal-bound-auth.md)) — the design that removes the preset `CONTROLPLANE_API_KEY` and `BRAIN_API_KEY`. The control plane runs every login (local passwords for development and test, OIDC, or IAP) and sets a session cookie that only the same-origin private `/api/` paths and the model gateway's admin API accept. The roles match the reference: user (the playground only), developer and admin, stored on principals and set by an admin in the console or by an optional IdP mapping. A first sign-in that no mapping matches gets user, and the first admin comes from a one-time setup code. API keys are created in the console, belong to a person or a service account, act with the owner's current role, and are accepted as `x-api-key` or Bearer. A session records its initiator, and the brain reaches the model gateway with a per-claim inference token instead of a shared key. The gateway drops per-key model grants for organization-wide rate limits per model. Seven slices, with no release between them; at the last one, every management API key without an owner stops working, which covers every key issued before slice 3.

- **The model gateway checks a credential and tests a deployment, on demand** ([#953](https://github.com/OpenSDLC-Dev/managed-agent-platform/issues/953)) — two admin routes call the vendor, and both need the admin role. `POST /admin/v1/providers/{id}/credentials/{cid}/check` lists the vendor's models with the credential's key, once on each protocol the key may use, and costs no tokens. Each protocol's result carries the vendor's status, its error, the latency and the model ids it listed. A profile's new `list_models` says where a check can list: DeepSeek's and Moonshot's Anthropic endpoints serve no such route, so a check answers from the profile there. `POST /admin/v1/deployments/{id}/test` sends one minimal request, a single token of chat or one short embeddings or rerank input, through the path an agent's call takes. It tests each enabled credential at once, or the one `credential_id` names: each once, without a retry, and within 30 seconds. Each result carries the vendor's status, the latency and the token usage, and, where the vendor answered whole, its own error type and message. Each request a test sends is written to the ledger under `api_key_id` `admin` and `endpoint` `deployment_test`. Neither route stores its result, and neither runs when a provider or a credential is created.

- **The `session.usage` event, and `usage.active_seconds` on the session** ([#432](https://github.com/OpenSDLC-Dev/managed-agent-platform/issues/432), plan 68) — every `session.status_idle` now comes immediately after a `session.usage` event, as on the reference, whatever the stop reason. It carries the session's cumulative token totals and `active_seconds`: the time at least one of the session's threads was running, with overlap counted once, to the millisecond. The session resource's `usage` carries `active_seconds` too, and counts a running session's open interval up to the read. Migration 0055 stores the running time and backfills it from the stored status events. It scans the event log before it locks the sessions table, then holds that lock while it updates the sessions with running time; an upgrade that also applies 0053 or 0054 holds it for the whole scan. Status events that a binary from before 0055 writes during a rolling upgrade can be miscounted, as the migration's comment describes. The event has no `list_cost` and no `server_tool_use`, and no snapshot follows a child thread's idle; budgets stay unbuilt.

- **The nightly eval suite now reports when it fails or stops** — a new scheduled workflow, `evals-alert.yml`, reads the `evals` run history every six hours and keeps one issue labelled `evals-failure` open while the newest verdict is a failure or is more than 48 hours old, then closes it when a run passes. A run that ends `cancelled` carries no verdict. The age check is the part a red job cannot report: from 2026-10-07 one run stuck in `waiting` held the `evals` concurrency group, every later scheduled run was cancelled, and no eval ran for ten days unnoticed (#950). The decision lives in `.github/scripts/evals-health.sh`, run by `make evals-alert-test` in CI.

- **Skills in a mounted repository are now announced to the agent** ([#921](https://github.com/OpenSDLC-Dev/managed-agent-platform/issues/921), plan 65) — a session that mounts a `github_repository` now gets the skills in the checkout's `.claude/skills/<name>/SKILL.md`, as the reference loads them. A skill with no frontmatter or no description is listed with an empty description. - **The model gateway is traced and metered** (plan 59 slice 2, [#890](https://github.com/OpenSDLC-Dev/managed-agent-platform/pull/890)) — each request is a server span that continues the caller's `traceparent`, with one client span per upstream attempt beneath it, carrying the model name sent, the upstream model that answered, the status, error and tokens. ### Changed

- **Native login for installs and delegated Brain calls** — The default Brain gateway route uses its current claim token for primary, child and grading requests. Direct provider routes retain vendor credentials. Compose defaults to development password login, and Helm requires a native login mode and Console origin. Acceptance, evals and CI obtain owned keys through setup and login; CI uses the browser cookie for gateway administration. Console manages keys for cloud and self-hosted environments. Staging configuration uses Google OIDC through the existing HTTPS edge, with its client secret supplied from Secret Manager. Compatibility receivers retain preset keys until plan 69 slice 7.

- **Principal-aware model gateway (plan 69 slice 4)** — Owned API keys call every configured model while their owner is an active developer or admin. Legacy keys keep their grants and key limits. Organization budgets share requests, input tokens and output tokens per minute across each public model alias. Native admin cookies set these budgets; developer cookies read them. Usage records the principal and credential, and daily totals combine a principal's keys. The bundled Console exposes budgets and principal usage. Historical totals and old gateway writers remain compatible. Pause and drain inference and diagnostics before the first updated service starts, until the usage backfill finishes. Drain old gateway replicas before relying on organization budgets. No release is cut before slice 7.

- **A Unicode hostname is refused in `allowed_hosts` and in an MCP server `url`, in the reference's words** ([#614](https://github.com/OpenSDLC-Dev/managed-agent-platform/issues/614)) — an environment's `allowed_hosts` and a vault credential's `auth.networking.allowed_hosts` now answer 400 `invalid_request_error` to an entry holding a non-ASCII character, such as `bücher.example`. Before, they accepted it and stored its A-label, `xn--bcher-kva.example`. An `allowed_hosts` entry stored earlier reads back unchanged, and an update that sends it back is accepted. An MCP server `url` holding a non-ASCII character now answers `mcp_servers.0.url: must be a valid URI` on agent create and update, a session create's override and a session update, each under its route's path; before, it was accepted. An agent or session stored with one still resolves, but an update that resends it is refused. Write the A-label instead: both lists accept it, though the reference refuses it in an environment's list. A percent-encoded host is still accepted. The executor's `WEBTOOL_ALLOWED_DOMAINS` still converts a Unicode name. [docs/DIVERGENCES.md](../../docs/DIVERGENCES.md) records the evidence.

- **Stored human roles, with no read-only tier (plan 69 slice 1)** — The control plane and gateway operator lane now use stored `user`, `developer` and `admin` roles. First unmatched sign-in gets user, which reaches only setup-code redemption. Reads and vault-credential writes require developer; memory redaction, API-key administration and environment-key administration stay admin-only. `IDENTITY_ROLE_MAP` is optional in both identity modes and applies on every verified request. Legacy `viewer` mappings now give user and lose read access: map readers to developer, which can also write. Older unexpired tokens can reapply their old mapped role. Deactivated principals stay refused. Principal DELETE and TRUNCATE now fail; replace retention DELETE jobs with the deactivated-row scrub in [the security guide](../../docs/self-hosted-security.md#8-principal-retention). Existing management keys remain unchanged in this slice. Releases are held until plan 69 slice 7.

- **A send to an archived session is refused in the reference's words** ([#58](https://github.com/OpenSDLC-Dev/managed-agent-platform/issues/58)) — `POST /v1/sessions/{id}/events` on an archived session still answers 400 `invalid_request_error`, before any event in the send is read. Its message is now "Cannot send events to archived session: <id>", as the reference was recorded answering, in place of "session <id> is archived and read-only". A client that matched the old text must match the new one.

- **Plan 42's slice 1 now includes its deployment plumbing** ([docs/plan/42_multi-tenant-activation.md](../plan/42_multi-tenant-activation.md) §7.1, [#615](https://github.com/OpenSDLC-Dev/managed-agent-platform/issues/615)) — a planning change; no deployment file changes. ### Security

- **Require native login and retire unowned API access (plan 69 slice 7)** — Both servers require a login mode and Console origin. Private APIs and gateway administration accept browser sessions only; public APIs accept owned keys with current-owner authorization. Unowned credentials and historical unowned initiators no longer authorize requests or model work. Gateway grants, key-policy routes and per-key admission are removed; organization limits share each public model alias. Compose, Helm and CD use the native-only Console and a Console-issued CD service-account key. Obsolete tables and existing staging Secret data remain temporarily for the separate cleanup deployment. Follow the [upgrade note](../../docs/UPGRADING_PLAN69.md) before rollout or rollback.

- **Initiator-bound execution** — Sessions, deployments and dreams retain the identity whose authority starts their model work. Removing a member or archiving a service account stops the next model turn; demotion alone does not. A scheduled run with a removed initiator fails and pauses its deployment. Native administrators can select an active service account for future scheduled runs. The gateway now accepts membership-checked inference tokens bound to one live claim and records the initiator's usage. The brain still sends its configured key until plan 69 slice 6. Existing unowned initiators continue through slice 6.

- **Principal-owned API keys (plan 69 slice 3)** — Owned keys now authenticate through `x-api-key` or issued-prefix Bearer with their owner's current stored role. Public `/v1` no longer admits IdP JWTs or proxy assertions. Private cookie login and the resource proxy remain available; owned keys cannot enter private administration or gateway inference. Owned Bearer companions cannot fall through to gateway operator assertions. Legacy unowned keys retain their existing `x-api-key` authority.
