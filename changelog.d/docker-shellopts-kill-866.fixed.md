- **A command past its deadline dies with its children on an image that sets `SHELLOPTS`** ([#866](https://github.com/OpenSDLC-Dev/managed-agent-platform/issues/866)) — on Docker, an image with `ENV SHELLOPTS` set to anything, even nothing, let the exec wrapper's job control (`set -m`) reach the command's shell through the exported variable. That shell put each of its jobs in a process group of its own, so the deadline's group kill took the shell and missed its children: the timeout was reported, and a `sleep 300` ran on until the container died. An image whose `SHELLOPTS` names `monitor` did the same on Docker, and worse on Kubernetes, where the command was reported as exiting 0, not timed out, while it ran on. Both exec wrappers now turn job control off before the command starts; the rest of the image's `SHELLOPTS` still reaches it. A startup file or command that turns job control back on itself takes its jobs out of the kill's reach, as `setsid` does ([image contract](docs/self-hosted-security.md)).
