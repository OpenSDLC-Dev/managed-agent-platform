- **A request body that is not valid UTF-8 is refused, on every JSON route** — Go's JSON decoder replaces an invalid byte with U+FFFD rather than rejecting it, so a body carrying one was accepted and stored altered; a memory's `content`, whose documented contract is valid UTF-8, was the surface where that showed (plan 36 slice 2, [#52](https://github.com/OpenSDLC-Dev/managed-agent-platform/issues/52)). Every JSON object body now answers `400 request body must be valid UTF-8` before it is parsed — JSON is UTF-8 by definition, so nothing legal is refused. A lone-surrogate escape (`\ud800`) is still decoded to U+FFFD, which is the decoder's documented behavior for an escape, not a byte the client sent.
