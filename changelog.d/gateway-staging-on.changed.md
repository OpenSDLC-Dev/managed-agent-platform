- **GCP staging runs the model gateway** ([#910](https://github.com/OpenSDLC-Dev/managed-agent-platform/pull/910), part of [#906](https://github.com/OpenSDLC-Dev/managed-agent-platform/issues/906)) — `staging-values.yaml` turns `modelgateway.enabled` on, so CD deploys the gateway, the brain sends every model call through it, and the mode-2 Secret carries `brain-api-key` in `model-providers.json`'s place. It runs one gateway replica, where the chart defaults to two, because at two the gateway's disruption budget holds `make gcp-env-stop`'s drain for up to an hour. Before its next deploy, staging's operator applies `foundation/` then `environment/`, creates `brain-api-key` in Secret Manager and sets the `MODELGATEWAY_SERVICE_ACCOUNT` repository variable; until the variable and the secret exist, the deploy stops at the step naming the missing one. The catalogue lives in Cloud SQL, so after every `environment/` rebuild someone adds the vendor key and an alias for the agents' model: `deploy/gcp/README.md` now gives the four admin calls, and notes that the default node pools need more SSD quota than a new project has. The deploy, the catalogue and a two-turn tool-using session were accepted on a rebuilt environment (`docs/HISTORY.md`).
