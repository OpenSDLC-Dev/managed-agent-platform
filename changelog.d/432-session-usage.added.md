- **The `session.usage` event, and `usage.active_seconds` on the session** ([#432](https://github.com/OpenSDLC-Dev/managed-agent-platform/issues/432), plan 68) — every `session.status_idle` now comes immediately after a `session.usage` event, as on the reference, whatever the stop reason. It carries the session's cumulative token totals and `active_seconds`: the time at least one of the session's threads was running, with overlap counted once, to the millisecond. The session resource's `usage` carries `active_seconds` too, and counts a running session's open interval up to the read. Migration 0055 stores the running time and backfills it from the stored status events. It scans the event log before it locks the sessions table, then holds that lock while it updates the sessions with running time; an upgrade that also applies 0053 or 0054 holds it for the whole scan. Status events that a binary from before 0055 writes during a rolling upgrade can be miscounted, as the migration's comment describes. The event has no `list_cost` and no `server_tool_use`, and no snapshot follows a child thread's idle; budgets stay unbuilt.
