- **The `session.usage` event, and `usage.active_seconds` on the session** ([#432](https://github.com/OpenSDLC-Dev/managed-agent-platform/issues/432), plan 68) — every `session.status_idle` now comes immediately after a `session.usage` event, as on the reference, whatever the stop reason. The event carries the session's cumulative token totals and `active_seconds`: the time during which at least one of the session's threads was running, with overlap counted once, to the millisecond. The session resource's `usage` carries `active_seconds` too; while the session runs, it reads as of the last idle. Migration 0055 stores the running time on each session and backfills it from the stored status events. It scans the event log once, and appends wait for the upgrade until it commits. A session that changes status while a replica on the earlier build still serves can be miscounted. The event has no `list_cost` and no `server_tool_use`, and no snapshot follows a child thread's idle; budgets stay unbuilt.
