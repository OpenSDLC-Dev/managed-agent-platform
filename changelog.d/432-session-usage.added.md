- **The `session.usage` event, and `usage.active_seconds` on the session** ([#432](https://github.com/OpenSDLC-Dev/managed-agent-platform/issues/432), plan 68) — every `session.status_idle` now comes immediately after a `session.usage` event, as on the reference, whatever the stop reason. The event carries the session's cumulative token totals and `active_seconds`: the time during which at least one of the session's threads was running, with overlap counted once, to the millisecond. The session resource's `usage` carries `active_seconds` too; while the session runs, it counts the interval still open up to the read. Migration 0055 stores the running time on each session and backfills it from the stored status events. It scans the event log once before it locks the sessions table, so appends go on during the scan; then every read and write of a session waits while the sessions with running time are updated, until the upgrade commits. An upgrade that also applies 0053 or 0054 runs the scan under the lock each takes on sessions in the same transaction, so there appends wait for the whole scan. A status event that a binary from before 0055 writes, or that commits during the scan, is reconciled from the log at the session's next status event; only an interval such a binary both opens and closes between two of that session's status events from this release goes uncounted. The event has no `list_cost` and no `server_tool_use`, and no snapshot follows a child thread's idle; budgets stay unbuilt.
