- **The deployment surface — CRUD, archive, pause and unpause** — plan 37 slice 1's routes ([docs/plan/37_scheduled-deployments.md](./docs/plan/37_scheduled-deployments.md), [#51](https://github.com/OpenSDLC-Dev/managed-agent-platform/issues/51)). A deployment binds an agent, pinned to a concrete version, to an environment, credentials, initial events and an optional 5-field POSIX cron schedule. Nothing fires yet (the manual run and the scheduler are later slices), so this adds the configuration a fire will read, and two timestamps derived from it. Neither is stored: `upcoming_runs_at` is recomputed per read, five occurrences whenever five exist, `[]` once archived and populated while paused; `last_run_at` is the most recent scheduled run's start, from which the published rules — manual runs do not move it, it survives archiving, it is null until one completes — all follow. `status` and `paused_reason` are rendered from the pause columns, so an archived deployment reports `active` and a paused one always carries a reason. Archiving is terminal for update, pause and unpause; `GET` still returns the row. Refused up front rather than at every nightly fire: a cron expression that can never fire, a file rubric with no object storage, and `budget` — no session budgets exist here, and an unenforced ceiling is worse than a 400 ([#432](https://github.com/OpenSDLC-Dev/managed-agent-platform/issues/432)). Repository tokens are sealed before the write and never echoed.
