- **`glob` reads only its own output and says when the image's bash is too old for it, and the sandbox tools refuse input too long to run** ([#827](https://github.com/OpenSDLC-Dev/managed-agent-platform/issues/827)) — On an image whose `ENV BASH_ENV` file printed — as it loaded, or from an `EXIT` trap it set — a `glob` answer carried those words as paths; `glob` now reads only what its own script printed between a begin and an end line, as `grep` does. On bash 3.2, which has no `globstar`, `glob` expanded `**` as `*` and answered without saying so; it is now a tool error naming the bash 4.0 it needs. A `glob` whose pattern and path make a command past the 120 KiB one exec argument can carry, and a `read`, `write` or `edit` whose `file_path` is longer than Linux allows — past 4095 bytes once resolved, or with a name past 255 — are refused before they run, with a tool error that says so, where such a path could fail the call as the sandbox's fault, retried until its lease ran out; and a `write` or `edit` whose `file_path`, quoted into the sandbox's own command, takes that command past the 120 KiB is a tool error naming the `file_path` too.
