- **A session thread's `stats` and `usage` are null until it has something to report, and the primary-archive refusal uses the reference's wording** ([#674](https://github.com/OpenSDLC-Dev/managed-agent-platform/issues/674), parts 3 and 4) — Both fields were objects from the moment a thread was created, where the reference renders `null` on a thread that has never run. Now `stats` appear at the thread's first status change and `usage` at its first idle, as the API spec states; a running thread cannot tell whether it has idled before, so there `usage` appears with the first model turn it settles instead. A client that read either field as always present must accept `null`. The session's own `stats` and `usage` are unchanged. Archiving a primary thread is still a 400 `invalid_request_error`, now with the reference's message: "The primary thread cannot be archived; archive the session instead."
