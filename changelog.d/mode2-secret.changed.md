- **One file assembles the mode-2 Secret, for CD and for an operator alike** ([#754](https://github.com/OpenSDLC-Dev/managed-agent-platform/issues/754)) — [deploy/gcp/mode2-secret.sh](./deploy/gcp/mode2-secret.sh) replaces the inline step in `deploy.yml` and the hand-maintained copy of it in [deploy/gcp/README.md](./deploy/gcp/README.md), which had already drifted: the workflow routes a missing `model-providers` container to the `gcloud secrets create` that fixes it (#755), and the operator's copy never got that, so the same fresh environment fails there with the raw `NOT_FOUND`. The two callers now differ only in `SECRET_DIR` — CD hands it one so a later step can re-read the api key, an operator lets the script make and remove its own. `make gcp-mode2-secret-test` runs it against a fake `gcloud` and `kubectl` and a real `jq`, holding every refusal it owes — a blank or whitespace-only version, an embedded newline in the two values read verbatim, five malformed `model-providers.json` shapes — and proving no credential reaches a command line. CI's seven-key guard reads the script now rather than the workflow.
