- **One file assembles the mode-2 Secret, for CD and for an operator alike** ([#754](https://github.com/OpenSDLC-Dev/managed-agent-platform/issues/754)) — [deploy/gcp/mode2-secret.sh](./deploy/gcp/mode2-secret.sh) replaces the inline step in `deploy.yml` and the hand-maintained copy of it in [deploy/gcp/README.md](./deploy/gcp/README.md), which had already drifted: the workflow routes a missing `model-providers` container to the `gcloud secrets create` that fixes it (#755), and the operator's copy never got that, so the same fresh environment fails there with the raw `NOT_FOUND`. Both callers run it with the same required inputs and disagree on one they pass: `SECRET_DIR` — CD supplies one so a later step can re-read the api key, an operator omits it and the script makes and removes its own. What else differs — the log masking, the run-summary annotations, `SECRET_CHANGED` — the script keys off `GITHUB_ACTIONS` itself rather than being told. `make gcp-mode2-secret-test` runs it against a fake `gcloud` and `kubectl` and a real `jq`, holding each refusal the assembly owes — a blank or whitespace-only version of either credential, an embedded newline in the two values read verbatim, five malformed `model-providers.json` shapes, a missing tool — and proving no credential reaches a command line. CI's seven-key guard reads the script now rather than the workflow, and also asks whether `deploy.yml` still runs it.
