- **A shared fixture corpus ties the two hand-written `.tf` readers together** ([#762](https://github.com/OpenSDLC-Dev/managed-agent-platform/issues/762)) — `deploy/gcp/check_split.py` and `tools/kmsrole/hcl.go` read the same Terraform subset in two languages and cannot share code, so until now they were kept in agreement by prose. That was not holding: three consecutive commits read the same heredoc rule three different ways, and each divergence was caught by a reviewer running the terraform binary rather than by a test. [tools/tfcorpus](./tools/tfcorpus) is the tie — whole `.tf` files with, beside each, the blocks a reader must return or the refusal it must give. Both suites read the same manifest, so a rule that moves in one reader and not the other now fails on the side that did not move. The new `make tf-corpus-check` re-asks terraform for each file's `fmt` exit, because a corpus written from a comment pins the comment and both of the boundaries this closes were rules the two readers agreed on and terraform did not. That exit is all terraform is asked: it says whether a file parses, never where the binary closed a heredoc, so a row's expected blocks stay held by the two readers having to agree.
