- **`make gcp-env-destroy` now recognises the four-day peering hold** ([#752](https://github.com/OpenSDLC-Dev/managed-agent-platform/issues/752)) — the target usually cannot finish in one run: deleting the service-networking connection is refused until Google releases the producer side, four days after the Cloud SQL instance behind it. Terraform prints that refusal, but not that the wait is four days, that stopping there is a legitimate end state, or that [docs/deploy-gcp.md](./docs/deploy-gcp.md) ("Tearing it down") has explained the whole thing since v0.2.0. When the refusal is in Terraform's error, the target now says so and points at the section. It explains that refusal only: the refusal can arrive beside an unrelated failure, so the message says stopping is legitimate *if* it is the only one, and leaves every other failure — a declined approval prompt included — to speak for itself. Exit status is unchanged.
