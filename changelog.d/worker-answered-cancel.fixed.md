- **A BYOC worker no longer runs a command nobody will read** — plan 35 decision 9 says an answered call is a cancelled call, in both exec drivers. The platform executor did that from the start; the customer-hosted worker ran every call under the shared work item's context alone, and a thread-scoped interrupt never stops that item. So interrupting one child thread left that child's `sleep 3600` burning customer compute to the tool timeout, and the result it then posted for a call the log had already answered was refused — aborting the whole pass and holding every sibling call behind it for a lease TTL. The worker now watches each call it runs the way the executor does, asking the session's log every ten seconds whether something else has answered it and cancelling the run when something has; the answer that lands after the last beat is dropped on the post instead, where a refused duplicate is now a skip rather than the run's fault. Refusals with any other cause — an ask still awaiting its human — still stop the pass, because the skip is bound to the call actually being answered and not to the status alone. ([#441](https://github.com/OpenSDLC-Dev/managed-agent-platform/issues/441))
