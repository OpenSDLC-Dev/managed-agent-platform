- **A slow MCP server no longer keeps the ones behind it out of the catalog, and one that cannot be reached is said out loud — plan 29 slice 6b (#45)** — The discovery pass dialled a session's declared MCP servers one after another, so position decided reach: a server that accepted a connection and never answered spent the whole pass budget, and the servers declared after it were recorded unreached on every turn for the life of the session — the model was never offered their tools. The pass now dials them all at once. It needs no width of its own, since `mcp_servers` is capped at 20 entries where it is written, and the rows stay in declaration order however the dials interleave. The same change bounds what a tarpit server holds: the executor's work goroutine is tied up for one server's dial-and-list rather than the sum of every declared server's, still capped by `EXECUTOR_MCP_PASS_TIMEOUT`. A discovery failure now also reaches the session log — `mcp_connection_failed_error`, or `mcp_authentication_failed_error` when the server refused the credential rather than failing to answer — naming the server, appended in the settlement's own transaction so the catalog row and the line about it commit together. It is said once, on the transition into failure, because the pass re-attempts a failed server every turn; a server the pass simply ran out of time on says nothing, since there is no connection behind it for an operator to heal.
