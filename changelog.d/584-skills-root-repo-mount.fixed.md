- **A repository can no longer be mounted over a session's skills** ([#584](https://github.com/OpenSDLC-Dev/managed-agent-platform/issues/584)) — skills land in `/workspace/skills/<dir>/`, and a `github_repository` named `skills` takes `/workspace/skills` as its default mount. Before this fix the API accepted that mount, and then every clone of it failed in the executor. It also accepted a path below it, like a skill's own directory, which nothing refused: the clone would replace that skill. When any agent of the session carries a skill (its own, an override's or a roster member's), session create, deployment create and deployment update now refuse a repository at or below `/workspace/skills` with 400. A deployment stored earlier records each fire as `session_creation_rejected_error` and keeps its schedule. A session with no skills may still mount a repository there, as the reference was recorded doing, and the executor now clones it instead of refusing it. `/workspace` itself, the default sandbox workdir, is now refused at create; before, the executor refused it after create.
