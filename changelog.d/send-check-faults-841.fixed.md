- **A database fault during an event send is a 500, not a 400 carrying the driver's text** ([#841](https://github.com/OpenSDLC-Dev/managed-agent-platform/issues/841)) — The checks a `POST /v1/sessions/{id}/events` batch runs against stored state could fail on a query error or a cancelled request. Those checks route an interrupt's thread claim, match tool results and confirmations to their calls, and validate `define_outcome`; session create's `initial_events` goes through the define-outcome check too. Every such failure was answered 400 `invalid_request_error` with the database error text as the message. The client was told the fault was its own, the SDK did not retry, and internal text left the server. These checks now return typed refusals for the client's mistakes, which keep their 4xx answers. Any other error takes the opaque internal 500.
