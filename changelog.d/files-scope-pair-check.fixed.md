- **A file's two scope columns can no longer disagree** — `files.scope_type` and `files.scope_id` were independently nullable, so a row could carry an id without a type. Both indexes on the table and the list's `?scope_id=` filter key on `scope_id` alone, while the file object is built only when both are present — so such a row was returned by a filter naming its scope and then rendered with no `scope` key at all. A new `CHECK` makes the pair move together. No writer in this platform could produce that row (the outputs harvest writes both columns in one statement; uploads write neither), so the migration is expected to validate everywhere — it is written to find that out rather than assume it (#659).
