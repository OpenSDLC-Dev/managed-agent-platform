- **Once-ever first-admin setup (plan 69 slice 1)** — With identity enabled and no admin-granting map, a never-bootstrapped install delivers a one-hour setup code per control-plane replica. Each code is stored only by hash in the database and delivered in an exclusive `0600` file inside a fresh `0700` temporary directory. Logs show only the path and expiry, never the code. Delivery failure stops startup; orderly return removes that process's file and directory. Same-UID, root and other file readers remain privileged: retrieve the code privately and redeem it promptly through the signed-in identity lane. Redeeming one spends every replica's code. Enabling an admin-granting map invalidates old codes at startup; replicas using that map also refuse redemption. Any first admin grant closes setup permanently, including a mapped admin; later demotion never reopens it. Invalid or expired codes and malformed request bodies no longer queue setup locks that block unrelated sign-ins. [The security guide](./docs/self-hosted-security.md#9-single-sign-on-and-the-bundled-identity-provider) covers retrieval, crash leftovers and SQL recovery. Member APIs, cookies, passwords and owned keys are not part of this slice.
