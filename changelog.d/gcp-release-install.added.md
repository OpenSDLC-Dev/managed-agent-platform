- **Installing a release into your own GCP project is documented** ([#749](https://github.com/OpenSDLC-Dev/managed-agent-platform/issues/749)) — every GCP instruction built the images into Artifact Registry first, so an operator deploying a *release* had to infer the rest. [docs/deploy-gcp.md](./docs/deploy-gcp.md) now has the path: the five `make` targets are unchanged, the build and install collapse into one `helm upgrade --install` from `oci://ghcr.io/opensdlc-dev/charts/managed-agent-platform`, the values file wants **no** `image:` block because the chart's defaults already resolve to that release's images, and `executor.gateImage` is the one image value it must set. It also names the trap: take `sandboxPlacement` from `deploy/gcp/staging-values.yaml`, not from `terraform output -raw helm_values_mode1`, whose `image:` mapping silently replaces those correct defaults with Artifact Registry coordinates the release never pushed to. `make gcp-env-tfvars` still needs the Cloud Build API and its default service account even though nothing builds. And [deploy/gcp/README.md](./deploy/gcp/README.md) now carries the `kubectl create secret generic` its own text promised: the seven-key mode-2 Secret previously existed as a worked command only inside `.github/workflows/deploy.yml`.
