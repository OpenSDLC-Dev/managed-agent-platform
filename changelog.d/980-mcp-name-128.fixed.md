- **An MCP tool's composed name may be up to 128 bytes, and a tool skipped for its name is reported on the session** ([#980](https://github.com/OpenSDLC-Dev/managed-agent-platform/issues/980)) — the brain now offers an MCP tool whose `mcp__{server}__{tool}` name is up to 128 bytes long, the Messages API's documented limit and the reference's recorded ceiling. It used to stop at 64. A longer name is still not offered, and the run's first request, or one that consumes a message sent mid-run, now records it as a `session.error` of type `mcp_connection_failed_error` in the reference's words, one per server, before the run carries on. An `mcp_servers[]` entry whose `name` is longer than 255 characters now answers 400 `invalid_request_error` `mcp_servers.0.name: maximum string length is 255` on agent create, under `agent.` on agent update and on a mid-session update, and as `agent.agent_with_overrides.config.mcp_servers.0.name: must be at most 255 characters` on a session create's override, in the words that route's recorded `system` refusal takes. A stored agent keeps resolving. A model route that speaks the OpenAI protocol still takes function names of at most 64 characters, so there an MCP tool whose composed name is 65 to 128 bytes now fails the whole request, as a custom tool of that length already did ([#981](https://github.com/OpenSDLC-Dev/managed-agent-platform/issues/981)).
