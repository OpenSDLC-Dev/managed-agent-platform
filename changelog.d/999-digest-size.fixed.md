- **A dream's digest size is a target to write to once, not a ceiling to trim to** — the pipeline's system prompt gave a digest's 4 KiB as a ceiling. When the model wrote a larger digest, its thread then rewrote it again and again, a little shorter each time. At a hundred transcripts the digest threads spent stage 2's 300-turn cap that way, and the dream failed with `internal_error`, or with `timeout` when its runtime budget ran out first. The prompt now gives 4 KiB as the size to aim at and says to write the digest once. A draft past 8 KiB is rewritten once, shorter; no other rewrite is made only to shorten a digest. It also says to state each fact once. The hundred-transcript eval now logs each stage's model turns, and each thread's turns, output tokens, time from first to last event, and tool calls, so a stage that runs long says which thread spent the turns.
