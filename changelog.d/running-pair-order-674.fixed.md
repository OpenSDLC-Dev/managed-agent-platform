- **The primary thread's running pair is emitted session-first, as the reference emits it** ([#674](https://github.com/OpenSDLC-Dev/managed-agent-platform/issues/674), part 2) — When the primary thread's move to running moves the session, `session.status_running` is now appended before the primary's `session.thread_status_running`; this platform had emitted the thread event first, where every `session.status_running` in the recorded reference sessions comes before the primary's. The primary's idle pair already matched the recordings (the thread event, then the session event) and is unchanged; `rescheduled`, never recorded, keeps the idle order. A child thread's resume of an idle session is not brought to the reference's shape: this platform pairs that `session.status_running` with the child's own thread event, now also session-first, where the reference pairs it with the primary's — recorded in docs/DIVERGENCES.md and left open on #674. Events already on the log keep the order they were written in, because the log is append-only; a client that reads a new running pair by position, on the list or the stream, sees the two swapped.
