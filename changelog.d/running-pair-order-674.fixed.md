- **The running status pair is emitted session-first, as the reference emits it** ([#674](https://github.com/OpenSDLC-Dev/managed-agent-platform/issues/674), part 2) — A thread moving to running now appends `session.status_running` before its `session.thread_status_running`; this platform had emitted the thread event first. Every running pair in the recorded reference sessions puts the session event first, stamped one microsecond ahead. The idle pair is unchanged and already matched the recordings: the thread event comes first, then the session event. `rescheduled`, which has never been recorded, keeps the idle order. Events already on the log keep the order they were written in, because the log is append-only. A client that reads a running pair's two events by position, on the list or on the stream, now sees them swapped.
