- **The primary thread's running pair is emitted session-first, the order the reference gives it** ([#674](https://github.com/OpenSDLC-Dev/managed-agent-platform/issues/674), part 2) — Wherever `session.status_running` is emitted beside the primary's `session.thread_status_running` (a session woken, a session created with `initial_events`, the brain's reclaim of a running session), it is now appended first; this platform had emitted the thread event first, where every `session.status_running` in the recorded reference sessions comes before the primary's. The idle pair already matched (the thread event, then the session event) and is unchanged; `rescheduled`, never recorded, keeps the idle order. Two differences stay open on #674, recorded in docs/DIVERGENCES.md: the pair still follows the `user.message` that wakes the session, where the reference writes it ahead of the message; and a child's resume of an idle session pairs `session.status_running` with the child's own thread event, now also session-first, where the reference pairs it with the primary's. Events already on the log keep their order, because the log is append-only; a client that reads a new running pair by position, on the list or the stream, sees the two swapped.
