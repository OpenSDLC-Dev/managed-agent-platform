- **The GCP executor identity can decrypt** ([#748](https://github.com/OpenSDLC-Dev/managed-agent-platform/issues/748)) — `deploy/gcp/environment/iam.tf` granted the executor `roles/cloudkms.cryptoKeyEncrypter`, on comments written before the executor decrypted anything. It decrypts in two places today: a `github_repository` clone opens the resource's sealed token (plan 25), and an MCP dial resolves a vault's bearer credential (plan 29). Encrypter alone is silent — the cipher's startup probe only encrypts, so the pods go Ready and the deploy is green — and then every clone fails, classified as a `session.error` with reason `internal`, and every vault-credentialed MCP dial as an authentication failure. The grant is now `roles/cloudkms.cryptoKeyEncrypterDecrypter`, and every comment that said otherwise — in the Terraform, the chart and the executor's own documentation — says what the code does. Affected is any Cloud KMS deployment whose executor identity holds Encrypter without the pair, however it got there: this Terraform granted exactly that, and the chart's README and `values.yaml` both told an operator separating the executor onto its own account to do the same. The remedy is one `gcloud kms keys add-iam-policy-binding` with the pair role, which is additive; a Terraform re-apply reaches the same place but *replaces* the binding rather than widening it, so prefer the additive form on a live deployment.
