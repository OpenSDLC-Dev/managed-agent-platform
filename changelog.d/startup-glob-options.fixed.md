- **The outputs harvest, `glob` and the `bash` tool work on an image whose startup sets glob options or an `ERR` trap** (found while working on [#921](https://github.com/OpenSDLC-Dev/managed-agent-platform/issues/921); [#935](https://github.com/OpenSDLC-Dev/managed-agent-platform/pull/935)) — an image's `ENV BASH_ENV` file runs before each of the platform's own scripts in the sandbox, and the settings it set carried into them. Under noglob (`set -f`) the outputs harvest published no files and `glob` matched nothing. A `GLOBIGNORE` hid matches, failglob made a `glob` that matched nothing an error, and nocaseglob or extglob changed what a pattern matched. An exiting `ERR` trap, which `set +e` leaves on, ended a platform script at a command the script let fail, and failed every `bash` call. Each script the platform runs in the sandbox for its own work now starts by clearing that trap and putting bash's defaults back for noglob, `GLOBIGNORE`, `GLOBSORT`, privileged mode and the `shopt` options `dotglob`, `extglob`, `failglob`, `globstar`, `nocaseglob` and `nullglob`; the `bash` tool's shell clears the trap as it turns errexit off. The repository-skills listing, which undid the glob settings itself since #933, now relies on the same start. The model's own commands still run under the glob settings the file set.
