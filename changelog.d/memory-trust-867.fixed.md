- **A memory store whose landing failed no longer turns untrusted for the sandbox's life** ([#867](https://github.com/OpenSDLC-Dev/managed-agent-platform/issues/867)) — when a store failed to land in a sandbox (a failed memories read or listing, a failed write), its directory could fill with no marker: the same run's sync pulled into it, the agent wrote into it, or the reaper's sync did. The next run then held the store untrusted and pull-only until the sandbox was replaced, and withheld every edit the agent made there. Now the executor and the BYOC worker write the marker first, with an empty baseline ahead of it, as soon as the directory is found empty and before the store is read. A landing that fails after that leaves a marked directory, and the next sync completes it: the store's memories are pulled, the agent's files are pushed, and the store wins any path both sides hold. A sync that finds an empty directory with no marker now lands it with the marker, as the reference worker does. This covers the run's syncs and the reaper's alike. A directory the marker never reached can still turn untrusted if the agent writes into it before a sync lands it. Examples are a failed marker write, a failed read of the store row on the executor, or a directory listing that does not answer.
