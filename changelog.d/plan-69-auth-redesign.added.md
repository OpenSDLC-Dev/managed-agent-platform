- **Plan 69 approved — principal-bound authentication** ([#997](https://github.com/OpenSDLC-Dev/managed-agent-platform/pull/997), [docs/plan/69_principal-bound-auth.md](docs/plan/69_principal-bound-auth.md)) — the design that removes the preset `CONTROLPLANE_API_KEY` and `BRAIN_API_KEY`. The control plane runs every login (local passwords for development and test, OIDC, or IAP) and sets a session cookie that only the same-origin private `/api/` paths and the model gateway's admin API accept. The roles match the reference: user (the playground only), developer and admin, stored on principals and set by an admin in the console or by an optional IdP mapping. A first sign-in that no mapping matches gets user, and the first admin comes from a one-time setup code. API keys are created in the console, belong to a person or a service account, act with the owner's current role, and are accepted as `x-api-key` or Bearer. A session records its initiator, and the brain reaches the model gateway with a per-claim inference token instead of a shared key. The gateway drops per-key model grants for organization-wide rate limits per model. Seven slices, with no release between them; at the last one, every management API key without an owner stops working, which covers every key issued before slice 3.
