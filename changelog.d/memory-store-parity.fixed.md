- **Three memory-store answers now match the reference's recorded ones** ([#684](https://github.com/OpenSDLC-Dev/managed-agent-platform/issues/684), [#685](https://github.com/OpenSDLC-Dev/managed-agent-platform/issues/685), [#686](https://github.com/OpenSDLC-Dev/managed-agent-platform/issues/686)) — Deleting a memory in an archived store now succeeds: an archived store still refuses new content with a 400, but admits erasure, so the delete writes its tombstone version and answers `memory_deleted`. A BYOC worker's local deletions in an archived store's mount therefore now reach the store, where the cloud executor still keeps them local. A delete whose `expected_content_sha256` is supplied but is not 64 lowercase hex characters is now a 400 `invalid_request_error` rather than a 409 — or, when supplied empty, rather than an unconditional delete; a well-formed digest that does not match is still the 409, and an absent one is still no precondition. Redacting a memory's current head version is now refused with a 400 in an archived store too, where it used to succeed and empty the memory; to erase a head there, delete the memory, then redact the version. A memory an earlier build emptied that way stays empty. Archiving a store still leaves its `updated_at` unmoved, which the reference does not (#685).
