- **The executor and the worker no longer take a status the image's startup chose as a step's answer** ([#942](https://github.com/OpenSDLC-Dev/managed-agent-platform/issues/942), plan 67 PR 3) — a checkpoint's restore, the package install, a repository's extraction and the memory sync's removals now take their exit status only where the script's own output frame arrived whole. Before, an image's `BASH_ENV` file that ended such a script's shell with status 0 marked a checkpoint consumed with nothing restored, recorded packages as installed, counted a repository as landed with no checkout, or wrote a memory baseline without files still on disk, so the next sync pushed memories the store had deleted back to it. Now each step fails as it does when its script fails, and the error names the image's startup. A memory store whose marker read the startup ended does not sync that pass, where before it synced pull-only.
