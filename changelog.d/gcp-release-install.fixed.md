- **Two guards in the CD deploy accepted values they should have refused** ([#749](https://github.com/OpenSDLC-Dev/managed-agent-platform/issues/749)) — `.github/workflows/deploy.yml` checks each credential it fetches from Secret Manager before assembling the mode-2 Secret, and two of those checks had holes. The `model-providers` shape check ran `jq -e` without `-s`, so `jq` evaluated each top-level document in the file in turn and `-e` took its status from the **last** one: a value holding two documents — a bare object followed by a valid array, which is what concatenating two route files or editing one in place produces — passed while the stored bytes were not a JSON array at all. And the empty-value check was `[ ! -s ]`, which a lone space passes, as does the newline check beside it; a blank api key is compared verbatim against a header the parser has already trimmed, and a blank DSN parses as no connection settings rather than as an error. Both now refuse: the filter is `jq -e -s 'length == 1 and (…)'`, and the emptiness test is `[ -z "$(tr -d '[:space:]' < …)" ]`. Nothing valid was made to fail — a pretty-printed array, a trailing newline, a multi-route array and a value with inner spaces all still pass. No deploy is known to have hit either: both were found by reviewing the checks.
