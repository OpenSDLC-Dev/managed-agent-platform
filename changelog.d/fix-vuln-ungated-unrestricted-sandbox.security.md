- **Unrestricted cloud sandboxes now provision the per-session egress gate and Helm enables it by default** — `internal/executor` now requests a per-session egress gate for every cloud session (including `networking.type: unrestricted` sessions without attached vaults) whenever `EXECUTOR_GATE_IMAGE` and `CONTROLPLANE_URL` are configured, routing outbound traffic through the gate's owner-match firewall and `dialguard.IPAllowed` address floor (blocking cloud metadata / link-local, loopback, unspecified, multicast, and embedded IPv6 transition targets). Existing sandboxes whose gate shape changes on upgrade are no longer deleted directly by `Provision`: the executor checkpoints and restores their workspace, deliverables, and shell state (failing closed intact if no object store is configured or capture fails). The Helm chart (`deploy/helm/managed-agent-platform/values.yaml`) now defaults `executor.gateImage` to `ghcr.io/opensdlc-dev/managed-agent-platform/gate:0.6.0`, which requires Kubernetes 1.29+ (native sidecars) and a namespace permitting `CAP_NET_ADMIN`; set `executor.gateImage=""` to opt out where a cluster or namespace does not meet those prerequisites. RFC 1918 destinations remain reachable under `unrestricted` networking by design and still require a Kubernetes `NetworkPolicy` or `networking.type: limited`.
