- **A file upload without a filename is stored, not refused** ([#738](https://github.com/OpenSDLC-Dev/managed-agent-platform/issues/738)) — `POST /v1/files` now follows the API reference's rule for the `file` part: only the final path component of the filename is kept, and an absent or empty one becomes `unnamed` plus the extension for the stored `mime_type` (`unnamed.pdf`; `unnamed.bin` for `application/octet-stream`), or a bare `unnamed` when the table knows no extension. Both used to be a 400, which the Go SDK reaches whenever `File` is given no name over a reader without one; a `\` is still refused. Five registry entries that plan 51's SDK read contradicted now say what their sources say — among them the work-item entry, which now weighs the SDK worker's own statement that the queue sends `healthcheck` items, and the memory-marker entry, whose collision premise the reference's worker never had.
