- **The role matrix — every route states what it needs, and a test proves none was forgotten** ([docs/plan/31_console-sso-rbac.md](docs/plan/31_console-sso-rbac.md) slice 3, [#56](https://github.com/OpenSDLC-Dev/managed-agent-platform/issues/56)) — slice 2 shipped the enforcement point with every route at the floor, denying every human; this annotates the **53 identity-reachable routes** with what each actually requires, relaxing that floor one route at a time rather than opening it wholesale. The split follows the plan's matrix: **23 `viewer`** reads across agents, environments, sessions, session resources, vaults, skills and files — the three adapter-free streaming routes (session events, skill archive download, file content) carry the same check explicitly, since a read is a read whether it arrives as JSON or as a stream; **25 `developer`** mutations covering resource CRUD and session lifecycle, including the vault *container*; and **5 `admin`** surfaces, which are exactly the credential-bearing ones — vault credential create, update, delete, archive, and the `mcp_oauth_validate` probe — joining the console environment-key routes slice 2 already gated. Two boundaries are deliberate and worth stating, because both look like mistakes until you know why: **vault credential *reads* stay `viewer`**, since they render sealed metadata and never a secret, while every write to one is `admin`; and the **environment-key surface is gated whole, listing included**, because which hosts hold live credentials and what they are named is itself the inventory an attacker would want. What did **not** change is the point: the nine registrations still carrying `RoleNone` are the eight work-API routes and the gate-config read, which identity never reaches, so there the value means "no role to check" rather than "denied" — and a worker's environment key, and the management `x-api-key`, pass through all of this exactly as before, which is asserted rather than assumed. Keeping those two readings of one constant apart is what the slice's completeness test is for: `TestEveryIdentityReachableRouteDeclaresARole` **parses the route table out of the source** and fails both on an identity-reachable route left at the floor and on a machine-lane route handed a role. It reads the source because nothing at runtime can — `http.ServeMux` does not expose its patterns, so a request-driven test can only check the routes someone remembered to list, which is precisely the failure being guarded against: a route added next year without a role would otherwise inherit deny-everyone silently and be discovered by a locked-out operator rather than by CI. Alongside it, `TestRoleMatrixIsEnforcedOnEveryRoute` drives all three tiers against every route over real HTTP and asserts the denial names the **route's** requirement and never the caller's own role — an operator's real question is "what does this need", and echoing their role back tells them nothing they did not just present. No route needs a real resource to answer that question: a 404 for a made-up id *is* the pass, because it means the check let the request through and the handler ran. The route table itself is untouched: extracting every registered pattern from `server.go` and diffing it against `main` comes back empty — same paths, same methods, same order — so nothing on the wire moved.
