- **An oversized MCP answer is kept, not just cut — plan 29 slice 4c (#45)** — A tool result is bounded twice over: it is the model's context, and it sits on an append-only log forever. So an MCP answer past that budget was truncated, and the rest was gone. It now lands whole in the session's sandbox, and the model is told the path — the bargain a built-in tool's oversized output has had since #226, and deliberately the same bargain: the same budget, the same `/tmp/tool_outputs/<call id>.txt`, the same notice. One convention, so a model that has learned where its truncated output goes is right whichever tool produced it. **What spills is the answer's text** — every text block and every text resource body, in the order the server sent them. An image or a blob is not written: those are bytes nothing useful reads back, they are bounded by the transport rather than truncated, and they keep the whole-or-nothing budget rule they already had — so the notice promises the text and only the text. It is a block of its own, after the answer and after the dropped-block notice, riding on top of the budget as that one does, because a pointer to the file holding the rest is worthless if the pointer is what gets cut. **A sandbox appears only when an answer needs one.** The MCP driver is server-side on every environment kind and never had a sandbox at all; it now provisions one lazily, at most once a pass, and only for an answer that overran — provisioning per pass regardless would put a container behind every MCP session on the platform, and per call would put several behind one turn. **A `self_hosted` session spills nothing**, and that is a deliberate divergence: its sandbox is the customer's, reachable only through a work API that has no MCP surface and no way to hand a file to a container this process does not own, so the answer truncates exactly as it did before. The reference's own behaviour there is unobserved. A failed provision or a failed write costs the call nothing either way — the answer is what it would have been, and the model is never pointed at a file that is not there.
