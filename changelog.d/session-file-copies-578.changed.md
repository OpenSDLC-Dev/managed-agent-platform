- **A mounted file is the session's own copy, as on the reference** ([#578](https://github.com/OpenSDLC-Dev/managed-agent-platform/issues/578)) — Every create, resources add and deployment fire mints a `files` row per file resource, echoed in `resources[].file_id`: a fresh id, session-scoped, never downloadable, with the upload's name, size, type and expiry. It shares the upload's object, not a copy of its bytes, so deleting the upload leaves the mount working; the object goes once no row names it. The default mount path and a deployment still name the upload. `GET /v1/files` without `scope_id` now leaves session-scoped files out, outputs included. Earlier sessions keep naming their uploads. **Upgrading:** migration 0046 locks `files` for its index builds (under 0.4s per million rows). Binaries roll in any order without loss, but an older replica, while it overlaps and after a rollback until each session is deleted, skips a copy's mount, lists copies unfiltered and to its grader, answers 404 deleting one and 500 to a rubric naming one or a worker reading one's content (the management route keeps its 400 `file_not_downloadable`), never sweeps an expired copy, keeping the upload's bytes and slowing its sweep, and, on a database defaulting stricter than READ COMMITTED, fails each delete that frees an object. While they overlap, either side's request can fail on a deadlock, `POST /v1/sessions` included. [docs/DIVERGENCES.md](docs/DIVERGENCES.md) registers what is inferred.
