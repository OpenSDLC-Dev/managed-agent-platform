- **A mounted file is the session's own copy, as on the reference** ([#578](https://github.com/OpenSDLC-Dev/managed-agent-platform/issues/578)) — Every create, resources add and deployment fire mints a `files` row per file resource, echoed in `resources[].file_id`: a fresh id, session-scoped, never downloadable, with the upload's name, size, type and expiry. It shares the upload's object, so deleting the upload leaves the mount working; the object goes once no row names it. The default mount path and a deployment still name the upload. `GET /v1/files` without `scope_id` now leaves session-scoped files out, outputs included. Earlier sessions keep naming their uploads. **Upgrading:** migration 0046 locks `files` for its index builds (under 0.4s per million rows). Binaries roll in any order without loss, but an older replica, while it overlaps and after a rollback until each session holding copies is deleted, skips a copy's mount, lists copies unfiltered and to its grader, answers 404 deleting one, 500 to a rubric naming one or a worker reading one's content (the management route keeps its 400 `file_not_downloadable`), never sweeps an expired copy, keeping the upload's bytes, slowing its sweep, and can fail a request, its own or this build's `POST /v1/sessions`, on a deadlock. On a database defaulting stricter than READ COMMITTED, each of its transactions that enqueues a `files/` key fails while it runs. [docs/DIVERGENCES.md](docs/DIVERGENCES.md) registers what is inferred.
