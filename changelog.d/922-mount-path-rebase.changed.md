- **A repository's `mount_path` is now rooted under `/workspace`, as the reference roots it** ([#922](https://github.com/OpenSDLC-Dev/managed-agent-platform/issues/922), plan 64; also [#584](https://github.com/OpenSDLC-Dev/managed-agent-platform/issues/584)) — a `github_repository` mounted at its literal path, and `/`, `/tmp` and `/mnt/memory` (with every path below it) were refused. Each path is now rooted under `/workspace`, matching every path the reference was recorded with: `/opt/repo` mounts at `/workspace/opt/repo`, `/tmp` at `/workspace/tmp`, and `/` or `/workspace` at the default `/workspace/<repo-name>`. A path that climbs out, like `../x`, is refused, and so are two repositories that meet once rooted. A repository may also share `/workspace/skills` with the session's skills, as the reference allows. Before, a clone at `/workspace/skills` failed in the executor, and one at a skill's own directory replaced that skill; repositories are now cloned before skills are written. Whatever the workdir, `/workspace` is now writable under a read-only root filesystem and kept by idle checkpoints. A deployment stored earlier keeps the path it resolved then, until its resources are sent again. A file can no longer overlay into a new checkout: files mount under `/mnt/session/uploads`.
