- **Memory stores omit `archived_at` until archived, and three update bodies now get the reference's answers** ([#817](https://github.com/OpenSDLC-Dev/managed-agent-platform/issues/817)) — Create, get, list and update rendered `"archived_at": null` on an unarchived store. They now leave the key out; an archived store still carries its timestamp. On `POST /v1/memory_stores/{id}`, three bodies now answer 400 `invalid_request_error` with the recorded message. A body naming none of `name`, `description` or `metadata` (`{}`), which used to be a 200 that changed nothing, says "at least one of name, description, or metadata must be provided". A null `metadata`, which used to keep the bag, gets the recorded parse error; a null inside the bag still deletes its key. A null `name` is now worded "name cannot be empty". The typed SDK reads a missing `archived_at` and a null alike. **Deploy order:** the first-party console typed the key as required, so roll out a console release carrying [managed-agent-console#185](https://github.com/OpenSDLC-Dev/managed-agent-console/pull/185) before this release. What the recordings leave open is in [docs/DIVERGENCES.md](docs/DIVERGENCES.md).
