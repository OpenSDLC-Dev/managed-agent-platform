- **Memory stores omit `archived_at` until archived, and null or empty update bodies get the reference's answers** ([#817](https://github.com/OpenSDLC-Dev/managed-agent-platform/issues/817)) — Create, get, list and update rendered `"archived_at": null` on an unarchived store; they now leave the key out, and an archived store still carries its timestamp. On `POST /v1/memory_stores/{id}`, `{}`, which was a 200 that changed nothing, is now a 400 "at least one of name, description, or metadata must be provided"; a null `metadata`, which kept the bag, gets the recorded parse error (a null inside the bag still deletes its key); and a null or empty `name` reads "name cannot be empty". Memory create and update give the recorded words for a null `content` or `path`, an empty update and a null precondition hash, e.g. "v1_update_memory_params: at least one of content or path must be provided". **Deploy order:** the first-party console typed `archived_at` as required, so roll out a console release carrying [managed-agent-console#185](https://github.com/OpenSDLC-Dev/managed-agent-console/pull/185) before this release. What the recordings leave open is in [docs/DIVERGENCES.md](docs/DIVERGENCES.md).
