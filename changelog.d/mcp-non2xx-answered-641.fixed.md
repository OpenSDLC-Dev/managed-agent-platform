- **An MCP tool call that fails at the HTTP layer is reported as a connection failure (#641)** — Some failed `tools/call` requests were read as the server's own refusal. The model got an `is_error` result, but the operator got no `session.error` at all. This happened when the call was answered 429, 500, 502, 503 or 504, with or without a body. It also happened when the connection dropped before any response arrived, or when any other non-2xx except 401 and 404 carried a JSON-RPC error body. The go-sdk reports the first two cases as a transport rejection that has the JSON-RPC error type, and it wraps the error it decodes from such a body. The client now treats a JSON-RPC error as the server's answer only when it arrives on a 2xx. A 2xx the platform's response-size limit refuses before reading counts as a connection failure too. These calls now emit `mcp_connection_failed_error` with `retry_status: retrying`, as a failed dial does. A 401 is still `mcp_authentication_failed_error`. A JSON-RPC error on a 2xx, such as an unknown tool, still goes only to the model. What the reference reports for a non-2xx on a call has not been observed yet (#78).
