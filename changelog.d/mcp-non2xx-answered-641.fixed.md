- **An MCP tool call answered with a non-2xx status is reported as a connection failure (#641)** — A `tools/call` answered 403, 407, 500, 502 or any other non-2xx status except 401, or a connection dropped mid-call, was read as the server's own refusal. The model got an `is_error` result, but the operator got no `session.error` at all. The go-sdk wraps a JSON-RPC error it decodes from a non-2xx body. It also turns 500, 502, 503, 504, 429 and HTTP-client failures into a rejection with the same error type, so a plain 500 or 502 needed no body to be misread. The client now treats a JSON-RPC error as the server's answer only when it arrives on a 2xx. These calls now emit `mcp_connection_failed_error` with `retry_status: retrying`, as a failed dial does. A 401 is still `mcp_authentication_failed_error`. A JSON-RPC error on a 2xx, such as an unknown tool, still goes only to the model. What the reference reports for a non-2xx on a call has not been observed yet (#78).
