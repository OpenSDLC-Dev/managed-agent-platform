- **On Kubernetes, a command that overran its deadline and then exited is reported as timed out, on a loaded cluster too** ([#832](https://github.com/OpenSDLC-Dev/managed-agent-platform/issues/832)) — a command that killed its in-pod watchdog, ran past its deadline and then exited could come back with `TimedOut: false` and its own exit code when the cluster was busy. The only witness was a liveness probe sent at the deadline plus 0.5 s, and that probe is itself an exec into the pod: under load it ran after the command had already exited. The exec wrapper now also records how long the command ran, from the pod's `/proc/uptime`, and a run longer than the deadline plus 0.5 s is a timeout whatever the probe saw. The record can only add a timeout, never remove one; the docker backend is unchanged.
