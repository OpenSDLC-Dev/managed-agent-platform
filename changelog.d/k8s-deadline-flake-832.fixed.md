- **On Kubernetes, a command that overran its deadline and then exited is reported as timed out, on a loaded cluster too** ([#832](https://github.com/OpenSDLC-Dev/managed-agent-platform/issues/832)) — a command that killed its in-pod watchdog, ran past its deadline and then exited could come back with `TimedOut: false` and its own exit code when the cluster was busy. The only witness was a liveness probe that is itself an exec into the pod, and under load it ran after the command had already exited. The exec wrapper now also records how long the command ran, from the pod's `/proc/uptime`. Against the deadline the watchdog enforces — the requested timeout rounded up to whole seconds — a run longer than it plus 0.5 s is a timeout whatever the probe saw, and so is a SIGKILL that ended a run reaching 50 ms short of it, which also covers a kill the watchdog did not deliver. The record only ever adds a timeout, never removes one; the docker backend is unchanged.
