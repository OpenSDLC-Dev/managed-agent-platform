- **Plan 38 drafted — multi-tenant activation** ([docs/plan/38_multi-tenant-activation.md](docs/plan/38_multi-tenant-activation.md), [#56](https://github.com/OpenSDLC-Dev/managed-agent-platform/issues/56)) — the design for the remaining half of #56: the reserved `org_id`/`workspace_id`/`project_id` columns become real scoping, with the **workspace as the isolation unit** and org and project frozen at `default`. Every credential resolves to exactly one workspace at authentication, every statement on a scoped table carries the predicate, and a resource in another workspace answers exactly as an absent one. Enforcement is application-level predicates behind a source-reading completeness guard modelled on `rolematrix_test.go`, plus a composite workspace foreign key as the database write floor; row-level security is rejected because the whole Postgres suite runs as superuser and would never exercise it. Six slices, the operator surface last so no intermediate release can be misconfigured into a half-enforced deployment; slice 1 waits on a live multi-workspace recording. Eight scope decisions were settled with the owner on 2026-09-03. The plan corrects the issue's inherited sizing (about 200 statements across 32 files, not 60–80 across 13), and the registry entry for the `anthropic-workspace-id` response header now also records that the request header is accepted and ignored.
