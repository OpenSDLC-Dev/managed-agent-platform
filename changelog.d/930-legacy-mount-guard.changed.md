- **A repository clone that fails in the sandbox after the fetch reports reason `internal`** ([#930](https://github.com/OpenSDLC-Dev/managed-agent-platform/issues/930)) — such a failure happens while the fetched repository is shipped into the sandbox or extracted there. Its `github_repository_clone_error` carried reason `network`, the git host's, whenever the error looked like a network failure. A dropped exec stream did, and so did a mount path such as `/workspace/EOF` in the error's text. It now carries `internal`, and a deadline there still carries `timeout`. A clone error is now deduped per resource, reason and message, not per resource and reason. So an occupied mount path's refusal reaches the client after an earlier generic `internal` failure.
