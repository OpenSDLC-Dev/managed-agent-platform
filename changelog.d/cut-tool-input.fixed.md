- **A tool call cut off at the output cap is answered instead of failing the turn** — when a response stops at max_tokens or model_context_window_exceeded and ends with a tool call whose input is an unfinished or empty object, the call used to fail the whole turn with a session.error, or run with no arguments. It is now committed with `{}` as its input, stamped `deny`, and the platform answers it in the same commit with an error result that says it was cut off and how the stream ended. Nothing runs it: `{}` would be a broader call for a tool whose arguments are all optional. The turn goes on, so the model can make the call again with shorter arguments, and a complete call in the same response runs beside it. A cut call to a tool the thread was not offered gets the answer any call to it gets. The reference dispatches the cut call with `{}` instead (docs/DIVERGENCES.md). An unfinished tool input under any other stop reason still fails its turn. The anthropic adapter also ends a tool block still open at message_stop under those two stop reasons instead of failing the stream, and the openai adapter reports finish_reason length as max_tokens on a turn with tool calls, where it used to report tool_use.
