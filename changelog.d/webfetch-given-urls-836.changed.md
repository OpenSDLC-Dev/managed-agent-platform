- **`web_fetch` finds a given URL in an index instead of reading the whole session** ([#836](https://github.com/OpenSDLC-Dev/managed-agent-platform/issues/836)) — Every fetch used to re-read the session's messages and web results, so its cost grew with the session. Migration 0048 adds an index of the URLs those events give, written as each event is appended, so a fetch is one lookup: about 1 ms at 10 fetched pages and at 400, where the old read took 55 ms at 400. The rule is unchanged: the same URLs are given and the same spelling is fetched. A payload too costly to index, such as a page of URLs run together, is still read at each fetch. The migration adds no rows. A session older than it is indexed on its first fetch: about 2.4 s for 1,000 fetched pages, once. The index costs about 200 bytes per URL reading, roughly 40 KB for a 100-link page, and appending a 100 KB web result takes about 7 ms longer. A URL whose host was spelled with a percent-escaped full-width letter, which the old read missed, is now found.
