- **An environment's `networking.allowed_hosts` is validated, and the gate dials the name it admitted (#609)** — The list was stored as arbitrary strings, and an entry matched only the literal string it was written as: a URL or a `host:port` therefore matched nothing a request could ever produce, and a typo read as the operator's fence when it was really a hole in it. Create and update now hold each entry to the grammar a vault credential's list has always used, and answer 400 otherwise. **Two shapes that did work are now refused at write time** — an IPv6 literal such as `::1`, and a label with an underscore such as `_acme.example.com` — because the published grammar admits neither; an operator relying on one must reach it another way. Rows stored before this keep working: they are not migrated, only what a patch newly supplies is checked, and an entry the row already holds is carried through, so reading a config back and posting it unchanged is not a 400. Separately, the gate's CONNECT handler dials the canonical name rather than the authority the sandbox wrote — admission and connection could otherwise name two different hosts — while a scoped address keeps its zone identifier exactly, since that names a local interface.
