- **An environment's `networking.allowed_hosts` is validated, and the gate dials the name it admitted (#609)** — The list was stored as arbitrary strings, so an entry that is not a hostname — a URL, a `host:port`, an IPv6 literal — silently matched nothing, and a typo read as the operator's fence when it was really a hole in it. Create and update now hold each entry to the grammar a vault credential's list has always used, and answer 400 otherwise. Rows stored before this keep working: they are not migrated, and only what a patch supplies is checked, so an update that never mentions `allowed_hosts` is never refused for what an earlier one stored. Separately, the gate's CONNECT handler now dials the canonical name rather than the authority the sandbox wrote — admission and connection could otherwise name two different hosts — and a conversion IDNA refuses is never acted on, so an entry like `xn--pypi-.org`, which converts to the real `pypi.org`, admits only itself.
