- **A memory version's `created_at` is the time it was written** ([#552](https://github.com/OpenSDLC-Dev/managed-agent-platform/issues/552)) — the memories API and a session's memory sync now stamp each `memory_versions` row with the database's `clock_timestamp()` at the insert, instead of the column default `now()`, which Postgres freezes when the transaction begins. Before, every version one sync wrote shared one `created_at` and listed in random id order, and a write that waited on the store lock listed below rows committed while it waited. Both now list in the order they were written, as far as the database clock keeps time; the list still orders on `created_at` and breaks a tie on `id`. A dream's clone of its input store keeps `now()`, because the dream's completion secret scan tells the clone's rows from the dream's own by that stamp. A memory's own `created_at` and `updated_at` keep `now()` too, so they can now fall before its head version's `created_at`.
