- **A memory version's `created_at` is the time it was written** ([#552](https://github.com/OpenSDLC-Dev/managed-agent-platform/issues/552)) — the memories API and a session's memory sync now stamp each `memory_versions` row with the database's `clock_timestamp()` at the insert, instead of the column default `now()`, which Postgres freezes when the transaction begins. Before, every version one sync wrote shared one `created_at`, and a write that waited on the store lock was stamped earlier than the rows committed while it waited. A dream's clone of its input store keeps `now()`: it writes into a store its own transaction creates, so nothing can wait on that lock, and the dream's completion secret scan tells the clone's rows from the dream's own by that stamp. The version list's order and paging are unchanged: they still break a tie on `id`.
