- **Two file-tool errors no longer tell the model to use `bash`** ([#634](https://github.com/OpenSDLC-Dev/managed-agent-platform/issues/634)) — when `write` or `edit` meets a target an atomic write cannot replace, or `read` or `edit` meets a file over the 4 MiB read limit, the tool result now states that constraint and names no tool. It used to advise bash redirection, or `head`/`tail`/`sed` on a slice, which sent a session with `bash` disabled, such as an `update_existing` dream, to a tool it was never offered and spent a turn on the refusal. A session that has `bash` can still use it.
