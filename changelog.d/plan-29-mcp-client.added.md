- **An MCP client, and one address guard under every customer-URL dial — plan 29 slice 2 (#45)** — `internal/mcp` is the platform's MCP client: a thin wrapper over the official `github.com/modelcontextprotocol/go-sdk`, which becomes a dependency of that package alone. `Connect` opens one connection to one server, `ListTools` reports what it offers, `Close` ends it — connections are per-work-item, which the protocol's 2026-07-28 revision makes cheap by removing protocol-level sessions: no handshake to amortize, and no affinity between discovering a server's tools and later calling one. The SDK's types stop at the package boundary; a tool reaches the rest of the platform as the platform's own `Tool`, JSON-tagged with the Anthropic field names (`input_schema`) so a stored catalog row needs no second translation before it is handed to a model. Pagination is followed to the end, up to a hundred pages, and a server offering no tools is a fact to record rather than an error — the reference documents an unknown MCP tool name as a warning, not a failure. **A server's answer is structure to be validated, not data to be trusted**, because the endpoint is customer-supplied and the SDK decodes a response rather than checking it. An entry the platform cannot faithfully hand to a model is skipped rather than failing the whole listing: an unusable name (empty, over 128 bytes, or outside `[A-Za-z0-9_.-]` — the MCP SDK's own rule, which it applies to a server registering a tool but not to a client reading one back), a schema that is present and is not a JSON object, one whose `type` is not `object`, and — MCP requires the field, so its absence is malformed rather than "takes no arguments" — a schema that is absent or null. What is *not* validated is the free text: a description is passed through as the server wrote it. A server that repeats its pagination cursor or never stops issuing new ones fails the listing rather than spinning inside a work item that holds a queue lease, and a body over 8 MiB or a listing over two minutes ends the same way, so trickling bytes cannot hold the lease either. A `"tools": [null]` response, which panics the SDK itself, is contained at the call rather than allowed to take down an executor shared by every session on the host. docs/DIVERGENCES.md records each of those readings, since none of them is reference behavior. **Transport is Streamable HTTP only.** The SDK negotiates every protocol version from 2024-11-05 up over it, so an older server is still reached; the separate HTTP+SSE transport of 2024-11-05 is deprecated in the spec, which tells new implementations not to adopt it, so the client-side fallback to it is split out rather than shipped with the base — docs/DIVERGENCES.md records the choice and what a legacy-only server sees until it lands. The standalone SSE stream is disabled: 2026-07-28 removed the GET endpoint it used, and a connection that asks one question and closes wants no server-initiated messages. **The dial guard is now one implementation, not two.** `internal/dialguard` holds the rule the vault-credential validate probe has enforced since plan 12 — loopback, link-local (cloud metadata), the unspecified address and multicast refused on the **resolved** IP of each dial it sees, including the IPv4 target embedded in an IPv6 transition address, so a DNS rebind cannot slip one past a name that resolved innocently a moment earlier — and the probe and the MCP client, the two places the platform resolves a host a customer named, now share it. RFC 1918 stays deliberately allowed: this platform's premise is on-prem operation, where an MCP server legitimately lives on the operator's own private network, so the guard is the floor beneath an agent's egress policy rather than the policy itself. The client the package builds for itself refuses to follow redirects, because following one replays the request and its `Authorization` header to a target the per-hop guard vets but never approved as a destination. A bearer token is then injected by wrapping a **copy** of the caller's HTTP client, and only for the endpoint's own origin — a second line that does not assume the first, since a caller may supply its own client (the seam a test needs) and that client's redirect policy is its own. Both halves are load-bearing: the copy stops the credential sticking to a client that may be shared, and the origin check stops it riding a redirect — `net/http` strips `Authorization` when a redirect changes origin, but only from headers set on the outbound request, and a header a RoundTripper adds is invisible to that logic, so without the check a `307` to another host would simply have the token added again. Nothing calls the client yet — the catalog and the executor's discovery driver are the rest of this slice.
