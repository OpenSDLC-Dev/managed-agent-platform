- **An MCP client, and one address guard under every customer-URL dial — plan 29 slice 2 (#45)** — `internal/mcp` is the platform's MCP client: a thin wrapper over the official `github.com/modelcontextprotocol/go-sdk`, which becomes a dependency of that package alone. `Connect` opens one connection to one server, `ListTools` reports what it offers, `Close` ends it — connections are per-work-item, which the protocol's 2026-07-28 revision makes cheap by removing protocol-level sessions: no handshake to amortize, and no affinity between discovering a server's tools and later calling one. The SDK's types stop at the package boundary; a tool reaches the rest of the platform as the platform's own `Tool`, JSON-tagged with the Anthropic field names (`input_schema`) so a stored catalog row needs no second translation before it is handed to a model. Pagination is followed to the end, and a server offering no tools is a fact to record rather than an error — the reference documents an unknown MCP tool name as a warning, not a failure. **Transport is Streamable HTTP only.** The SDK negotiates every protocol version from 2024-11-05 up over it, so an older server is still reached; the separate HTTP+SSE transport of 2024-11-05 is deprecated in the spec, which tells new implementations not to adopt it, so the client-side fallback to it is split out rather than shipped with the base — docs/DIVERGENCES.md records the choice and what a legacy-only server sees until it lands. The standalone SSE stream is disabled: 2026-07-28 removed the GET endpoint it used, and a connection that asks one question and closes wants no server-initiated messages. **The dial guard is now one implementation, not two.** `internal/dialguard` holds the rule the vault-credential validate probe has enforced since plan 12 — loopback, link-local (cloud metadata), the unspecified address and multicast refused on the **resolved** IP of every dial, including the IPv4 target embedded in an IPv6 transition address, so a DNS rebind cannot slip one past a name that resolved innocently a moment earlier — and both callers now share it. RFC 1918 stays deliberately allowed: this platform's premise is on-prem operation, where an MCP server legitimately lives on the operator's own private network, so the guard is the floor beneath an agent's egress policy rather than the policy itself. Redirects are never followed, because following one replays the request and its `Authorization` header to a target the per-hop guard vets but never approved as a destination. A bearer token is injected by wrapping a **copy** of the caller's HTTP client, so a credential resolved for one server cannot ride along to the next over a shared client. Nothing calls the client yet — the catalog and the executor's discovery driver are the rest of this slice.
