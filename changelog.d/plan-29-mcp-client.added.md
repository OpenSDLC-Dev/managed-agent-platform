- **An MCP client, and one address guard under every customer-URL dial — plan 29 slice 2 (#45)** — `internal/mcp` is the platform's MCP client: a thin wrapper over the official `github.com/modelcontextprotocol/go-sdk`, which becomes a dependency of that package alone. `Connect` opens one connection to one server, `ListTools` reports what it offers, `Close` ends it — connections are per-work-item, which the protocol's 2026-07-28 revision makes cheap by removing protocol-level sessions: no handshake to amortize, and no affinity between discovering a server's tools and later calling one. The SDK's types stop at the package boundary; a tool reaches the rest of the platform as the platform's own `Tool`, JSON-tagged with the Anthropic field names (`input_schema`) so a stored catalog row needs no second translation before it is handed to a model. Pagination is followed to the end, and a server offering no tools is a fact to record rather than an error — the reference documents an unknown MCP tool name as a warning, not a failure. **Everything a server sends is treated as hostile until checked**, because the endpoint is customer-supplied and the SDK decodes a response rather than validating it: a nameless tool or a non-object schema is skipped rather than failing the whole listing, an absent schema becomes the empty object schema Anthropic's `input_schema` requires instead of the `null` a model API rejects, and a server that repeats its pagination cursor or never stops issuing new ones fails the listing rather than spinning inside a work item that holds a queue lease. A `"tools": [null]` response, which panics the SDK itself, is contained at the call rather than allowed to take down an executor shared by every session on the host. docs/DIVERGENCES.md records each of those readings, since none of them is reference behavior. **Transport is Streamable HTTP only.** The SDK negotiates every protocol version from 2024-11-05 up over it, so an older server is still reached; the separate HTTP+SSE transport of 2024-11-05 is deprecated in the spec, which tells new implementations not to adopt it, so the client-side fallback to it is split out rather than shipped with the base — docs/DIVERGENCES.md records the choice and what a legacy-only server sees until it lands. The standalone SSE stream is disabled: 2026-07-28 removed the GET endpoint it used, and a connection that asks one question and closes wants no server-initiated messages. **The dial guard is now one implementation, not two.** `internal/dialguard` holds the rule the vault-credential validate probe has enforced since plan 12 — loopback, link-local (cloud metadata), the unspecified address and multicast refused on the **resolved** IP of every dial, including the IPv4 target embedded in an IPv6 transition address, so a DNS rebind cannot slip one past a name that resolved innocently a moment earlier — and both callers now share it. RFC 1918 stays deliberately allowed: this platform's premise is on-prem operation, where an MCP server legitimately lives on the operator's own private network, so the guard is the floor beneath an agent's egress policy rather than the policy itself. Redirects are never followed, because following one replays the request and its `Authorization` header to a target the per-hop guard vets but never approved as a destination. A bearer token is injected by wrapping a **copy** of the caller's HTTP client, and only for the endpoint's own origin. Both halves are load-bearing: the copy stops the credential sticking to a client that may be shared, and the origin check stops it riding a redirect — `net/http` strips `Authorization` when a redirect changes origin, but only from headers set on the outbound request, and a header a RoundTripper adds is invisible to that logic, so without the check a `307` to another host would simply have the token added again. Nothing calls the client yet — the catalog and the executor's discovery driver are the rest of this slice.
