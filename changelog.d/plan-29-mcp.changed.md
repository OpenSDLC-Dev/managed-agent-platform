- **Agent toolset configuration is echoed resolved, and an `mcp_toolset` is now validated like its built-in twin — plan 29 slice 1 (#45)** — Three wire rungs an MCP-configured agent needs before any MCP client exists. **Resolved config echo:** every read of an agent — create, get, a pinned version, the list — and every resolved-agent snapshot on a session now renders both toolset kinds with `configs` and `default_config` present and each `enabled` / `permission_policy` inside them concrete, which is what the reference's response types require of `agent_toolset_20260401` and `mcp_toolset` alike; a bare `{"type":"mcp_toolset","mcp_server_name":"docs"}` comes back carrying `configs: []` and a `default_config` of `{"enabled":true,"permission_policy":{"type":"always_ask"}}`, the built-in kind resolving to `always_allow` instead. Resolution happens at render, so stored rows still hold the client's own bytes, agents written before this change echo resolved without a backfill, and an update still merges against what was actually sent. **Dangling toolsets are rejected:** an `mcp_toolset` naming a server absent from `mcp_servers` is a 400 on every surface that resolves a whole spec — agent create, agent update's merged result, a session's `agent_with_overrides`, and a session-update `agent.tools` patch. Only the mirror-image rung (a declared server no toolset references) was enforced; the reference's public MCP-connector guide states both directions, so the earlier reading — recorded as deliberate under #66 on the strength of the SDK's param docs alone — is corrected rather than retired quietly, and docs/DIVERGENCES.md says which way it moved. **`mcp_toolset` shape validation:** an unknown key anywhere in the `default_config` / `configs[]` / `permission_policy` nest, or a `permission_policy.type` outside the two-value enum, is now a 400 naming the field's path. `parseTools` had checked only that `mcp_server_name` was non-empty, so a misspelled `permission_polciy` was dropped by `encoding/json` and the tool silently resolved to the toolset default — the fail-open that #26 closed for the built-in toolset, still open on the one kind whose default is to stop and ask a human. A Messages-API-only key such as `defer_loading` is refused here too: the two MCP schemas are deliberately different and must not be conflated. **Along the way, one long-standing inference is retired:** the built-in toolset's `always_allow` default was recorded as unconfirmed (#59) because the SDK's wire types carry no resolved default; the public permission-policies guide states it outright, twice, so docs/DIVERGENCES.md now records both toolset defaults as documented rather than inferred.
