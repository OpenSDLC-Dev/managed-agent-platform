- **A memory's `created_at` and `updated_at` are the time it was written** ([#975](https://github.com/OpenSDLC-Dev/managed-agent-platform/issues/975)) — the memories API and a session's memory sync now stamp a memory with the database's `statement_timestamp()`, the start of its insert or update, which comes after the store lock. They used to take the column default `now()`, which Postgres freezes when the transaction begins. So a create that waited on the store lock listed behind memories committed while it waited, and every memory one sync created shared one `created_at` and listed in random id order. New memories now list in the order their creates committed, as far as the database clock keeps time, and so agree with the memory-versions list. Memories written before this release keep their stamps. At create the two stamps are one reading, so they are equal, as on the reference. A memory is stamped just before the version its write records, as on the reference, now by the time between two statements rather than by a lock wait. A dream's clone of its input store keeps `now()`, so its memories still share one `created_at`, and the list breaks that tie on `id`.
