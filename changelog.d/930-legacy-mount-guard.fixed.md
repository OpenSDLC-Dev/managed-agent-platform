- **A repository stored before #922 no longer removes what the image ships outside the platform's directories** ([#930](https://github.com/OpenSDLC-Dev/managed-agent-platform/issues/930)) — such a repository keeps the literal `mount_path` it was stored with, which can lie outside the platform's own directories. A clone replaced whatever was at that path when the sandbox user could remove it, so one stored at `/usr` could remove the image's own programs. A clone now replaces a path whole only below `/workspace`, the workdir, `/tmp`, `/mnt` or the shell state directory. Elsewhere it takes only an absent path or an empty directory the sandbox user can remove. At a path that holds anything, such as `/usr` or `/etc`, it fails with a `github_repository_clone_error` and leaves the path as it was. A repository at a path the image does not ship, such as `/opt/repo`, still clones, because a new sandbox has nothing there. A checkout there that lost its `.git` now fails instead of being replaced. Sending a deployment's resources again roots its paths under `/workspace`. A failure in the sandbox after the fetch, whose text could read as the git host's, now carries reason `internal`, not `network`.
