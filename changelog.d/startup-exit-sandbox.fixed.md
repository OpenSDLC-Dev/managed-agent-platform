- **An image whose startup file ends the shell no longer forges a sandbox script's answer** ([#942](https://github.com/OpenSDLC-Dev/managed-agent-platform/issues/942), plan 67 PR 1) — an image's `BASH_ENV` file runs first in every shell, and one that exits ends the shell before the platform's script begins; the exec then reports the startup's status. Before, a status of 0 reported a write or a batch write that never happened, and on Kubernetes a refusal status reported a present file as missing. On both backends, a file write, a batch write's steps, the Kubernetes read and the Kubernetes exit record now take a status only where the script's own output frame arrived. Otherwise the call fails with an error that names the image's startup and the status it left, and a tool call answers it as a tool error. A probe that only classifies a refusal the backend already has answers nothing, so the refusal stays unclassified.
