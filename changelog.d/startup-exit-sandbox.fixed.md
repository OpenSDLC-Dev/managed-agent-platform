- **An image whose startup file ends the shell no longer forges a sandbox script's answer** ([#942](https://github.com/OpenSDLC-Dev/managed-agent-platform/issues/942), plan 67 PR 1) — an image's `BASH_ENV` file runs first in every shell, and one that exits ends the shell before the platform's script begins; the exec then reports the startup's status. Before, a status of 0 reported a write or a batch write that never happened, and on Kubernetes a refusal status reported a present file as missing. On both backends, a file write and a batch write's steps, and on Kubernetes a file read, now take a status only where one stream carries the script's own output frame whole. Where neither stream shows the script began, the call fails with an error that names the image's startup and the status it left, and a tool call answers it as a tool error; at the bash tool's `done` marker the call's result comes back unsaved. A script that began and whose output was lost on its way fails as a transport fault. On Kubernetes, an exit record whose reader the startup ended fails with the error that names the image's startup, rather than read as no record. A probe that only classifies a refusal the backend already has answers nothing, so it gives the refusal no reason. A framed script also clears an `EXIT` trap the startup set, which could otherwise replace its status.
