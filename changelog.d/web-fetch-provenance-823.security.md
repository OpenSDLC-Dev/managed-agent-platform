- **`web_fetch` fetches only a URL the session was given** ([#823](https://github.com/OpenSDLC-Dev/managed-agent-platform/issues/823)) — The tool's description, the reference's word for word, says it fetches only URLs the user provided or a `web_search` or `web_fetch` result returned, but nothing enforced it: a model a prompt injection had turned could build a URL carrying a secret and fetch it, bounded only by the operator allowlist. The executor now refuses any other URL with an error result before fetching. A URL counts as given when it appears in a user message on any of the session's threads, or in a successful `web_search` or `web_fetch` result, a fetched page's links included. Messages between agents, failed results and other tools' output do not count. URLs are compared with the scheme and host lowercased and the fragment dropped; the path and query must match exactly. Redirects stay unchecked: the reader backend follows them itself and does not report where it landed ([#831](https://github.com/OpenSDLC-Dev/managed-agent-platform/issues/831)). An agent that relied on fetching a URL it composed, or a bare domain written without `https://`, now gets an error and can find the page with `web_search` first.
