- **Egress gate now enforces concurrent work, aggregate body-buffering, and container resource limits** ([#1052](https://github.com/OpenSDLC-Dev/managed-agent-platform/issues/1052); [plan 70](docs/plan/70_security-hardening-vault-egress.md) slice 2) — `internal/gate` now bounds concurrent plain-HTTP requests (default 64), concurrent CONNECT tunnels (default 64), aggregate plain-HTTP body buffering (default 32 MiB, reserved incrementally during reads and placeholder substitution), body read stalls (default 30 s), and outbound upload stalls (default 60 s) through a `Limiter` shared across `gaterun.SwappableHandler` policy swaps, while `cmd/gate` sets `http.Server.MaxHeaderBytes` to 64 KiB. Over-budget traffic returns `503` (or `408` on a stalled inbound upload) without blocking ordinary requests, and outbound request body buffers and reservations are released when `http.Transport` closes the upload body. Both the Docker and Kubernetes sandbox providers now apply independent default resource limits to the gate container (256 MiB memory and 500m CPU on both, plus 128 PIDs on Docker) even when sandbox memory limits are disabled.
