- **Thread messages name their peers the way the reference does** ([#675](https://github.com/OpenSDLC-Dev/managed-agent-platform/issues/675)) — `agent.thread_message_received` always names its sender now: a message from the coordinator carries its session agent's name in `from_agent_name`, which was `null`. `agent.thread_message_sent` names its target only when that target is a child, so a child's message to its coordinator omits `to_agent_name` instead of sending `null`. Both follow a recording of the reference, which contradicts the SDK's note that `from_agent_name` is absent for the primary agent. A client reading `to_agent_name` must accept the key being absent; the console already does. Rows already stored keep their nulls, and the model sees no change: replay still renders any message from the coordinator, old row or new, as `[message from your coordinator]`, so no child's cached request prefix moves.
