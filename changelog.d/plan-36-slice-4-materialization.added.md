- **A `cloud` session's memory stores are mounted, told to the agent, and synced back** (plan 36 slice 4, [#52](https://github.com/OpenSDLC-Dev/managed-agent-platform/issues/52)). The executor lands every attached store at `/mnt/memory/<slug>` before the tools run — the memories as `0666` files beside a marker and a baseline — and the brain renders a "Memory stores" block after the repositories block: each mount with its access, description and instructions, an archived store read-only, a deleted one unavailable. When a tool run ends the directory is reconciled with the store in three phases: the tree is hashed (a listing that fails skips the store rather than reading as deletions), the changes settle inside the transaction that commits the run (pushes carry a compare-and-set and a `session_actor` version; the store wins a both-sides change; a mount emptied of a baseline's several files is re-downloaded, marker and all, never treated as deletions), and the settlement is written back. A `read_only` or archived store, or a directory whose marker was altered, is pulled from and never pushed to; `write`/`edit` refuse a `read_only` or archived store's files and any path under `/mnt/memory` outside a store; the reaper syncs a sandbox before every reap but a deleted session's. `FileWrite.Mode` on both sandbox backends, two evals (`memory-recall`, `memory-write`), five telemetry instruments, four registry entries ([docs/DIVERGENCES.md](./docs/DIVERGENCES.md)).
