- **`internal/identity` — the human-authentication boundary** ([docs/plan/31_console-sso-rbac.md](docs/plan/31_console-sso-rbac.md) slice 1, [#56](https://github.com/OpenSDLC-Dev/managed-agent-platform/issues/56)) — a strict, vendor-SDK-free OIDC relying party the platform can point at any compliant provider, plus a trusted-proxy mode for deployments where a cloud vendor terminates authentication. `Verify` authenticates one compact JWT and returns a principal carrying one of three claim-mapped roles (`viewer` < `developer` < `admin`): the signature allowlist is a required argument to the parser, so `alg:none` and HS256 are refused before any key is looked up; a `crit` header is refused outright, before the key lookup, because the JOSE library's own check permits `crit:["b64"]` while RFC 7797 forbids `b64` in a JWT at all; `iss` is exact, `aud` must contain the configured audience, `azp` is checked when `aud` names several, and a non-empty `sub` and an `exp` are required because the JOSE library checks neither. Key material lives in a kid-indexed cache with a **bounded lifetime** — a five-minute TTL checked before the map lookup, so a key the provider removes stops verifying within that bound instead of living in the cache forever — behind a refresh cooldown, single-flight, a per-fetch deadline, a body cap, no redirects, and the same address guard the MCP client dials through. Every rejection is one error type whose message is a constant string, with the detail behind `Reason()` for the operator's log: nothing distinguishes expired from bad-signature from wrong-audience to a caller. No log line and no error carries a token byte or a URL credential — a key-set URL can be a *signed* URL whose query string is the credential, so every URL is redacted on its way to a log or an error, including inside a transport error (whose own message quotes the URL verbatim, so its cause is wrapped instead and `errors.Is` still reaches the deadline underneath). Roles come from a configurable claim on every request and are never stored (the provider stays authoritative), reduced to the single strongest mapped value by rank so neither claim order nor map iteration order can change the answer, and a dotted claim name resolves as a path only — never additionally as a flat key of that name, which is the direction that would let a user-settable claim outrank a nested one. The role map is validated *and copied* at construction, so an empty claim value or a role outside the three fails startup, and the policy stops being editable — a caller that still holds the map it passed in cannot race a live `Verify` or silently change who is an admin. `IDENTITY_MODE` is `disabled` by default and the platform is then byte-for-byte what it was; every other misconfiguration fails startup rather than open, including an issuer URL carrying a query or a fragment, which an OIDC issuer identifier may not have and which would break both the exact `iss` comparison and the discovery URL built by appending to it. No route consumes this yet — the identity lane, principals and the role matrix are the following slices — and the `/v1` wire, the `ant` CLI and machine credentials are untouched. The plan's own dependency choice was overturned here on evidence and the reasoning is in [docs/HISTORY.md](docs/HISTORY.md): `coreos/go-oidc` cannot express the bounded key lifetime the plan requires, and hand-rolling JOSE would have removed nothing from a binary that already links `go-jose` transitively.
