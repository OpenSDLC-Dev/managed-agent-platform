- **Environment-key tests now pin the invariants their comments claim** ([#362](https://github.com/OpenSDLC-Dev/managed-agent-platform/issues/362)) — review of plan 30 slice 2 found four test defects slice 1 had introduced, on security-adjacent invariants; all four are fixed here rather than carried as backlog, and no production code changed. One assertion genuinely could not fail: the index pin for `environment_keys(environment_id)` matched on `indexdef LIKE '%(environment_id)%'`, a pattern the *dropped* `environment_keys_one_live` index satisfied too, so a database where migration 0021 created nothing and dropped nothing still passed the one check meant to catch exactly that — proven by probe, then fixed to match the index by name, to reject a partial index, and to assert the retired one-live index is gone. One assertion was missing rather than weak: slice 1 deleted the test that polled the work queue with a shared key value against both environments over real HTTP — 200 for its own, 401 for the other — and replaced it with "the raw INSERT is rejected", which only exercises the `key_hash` UNIQUE constraint and leaves the escalation unpinned at the HTTP layer; the live half is restored and is falsifiable, since disabling the work API's environment-scope comparison turns it red where the pre-fix test stayed green under the identical mutation. Two ordering assertions could already fail, but at random and for a reason unrelated to the behaviour under test: `ORDER BY created_at DESC, id DESC` over rows whose `created_at` defaults to `now()` falls through to a 120-bit random tiebreak when two keys are issued inside one microsecond, so what the listing returned was decided by clock resolution rather than by the query. Timestamps are now set explicitly in one statement, the paging test pins both pages instead of only its last row, and a new test collapses eight keys onto a single `created_at` to pin the id tiebreak that the flake had been hiding. The fourth fix is documentation only and changes no test outcome: `raceMints`'s doc comment still described the retired rotate-on-mint contract, and now states the helper's own contract and what each of its three callers requires of it.
