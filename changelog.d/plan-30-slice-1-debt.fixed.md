- **Four environment-key tests that could not fail now can** ([#362](https://github.com/OpenSDLC-Dev/managed-agent-platform/issues/362)) — review of plan 30 slice 2 found that slice 1 had left behind assertions weaker than their own comments claimed, on security-adjacent invariants. The index pin for `environment_keys(environment_id)` matched on `indexdef LIKE '%(environment_id)%'`, a pattern the *dropped* `environment_keys_one_live` index satisfied too — so a database where migration 0021 created nothing and dropped nothing still passed the one check meant to catch exactly that; proven by probe, then fixed to match the index by name and to assert the retired one-live index is gone. `TestEnvironmentKeyValueBindsToOneEnvironment` had been reduced to "the raw INSERT is rejected" when the test it replaced also asserted, over real HTTP, that a shared key value authenticates only its own environment — the escalation itself was unpinned at the HTTP layer, and the restored half is falsifiable: disabling the work API's environment-scope comparison turns it red where the previous version stayed green. Listing-order assertions no longer depend on two `now()` calls landing in different microseconds, which would otherwise fall through to a random-id tiebreak and flip at random; timestamps are spread explicitly, so "newest first" is what is tested and both pages' contents are now pinned rather than only the last row. And `raceMints`'s doc comment, which still described the retired rotate-on-mint contract, now states the helper's own contract and records that two of its three callers require *every* concurrent mint to succeed — the per-host property migration 0021 exists to provide. No production code changed.
