- **Only a worker's credential may post a `user.tool_result`** ([#662](https://github.com/OpenSDLC-Dev/managed-agent-platform/issues/662)) — `POST /v1/sessions/{id}/events` now decides who may answer a tool call by the credential that signed the request, as the reference does, rather than by the session's environment kind. A management `x-api-key` or a human's identity token posting a `user.tool_result` is refused 403 `permission_error` on any session, and a batch carrying one appends nothing. On a `self_hosted` session a management key used to be accepted, so it could answer a call the worker was to answer; on a `cloud` session the refusal was a 400. The environment key and the per-item sessions token are still accepted, so the BYOC worker and `ant beta:worker` are unaffected. A client that posted tool results with a management key must send them with the environment's key instead.
