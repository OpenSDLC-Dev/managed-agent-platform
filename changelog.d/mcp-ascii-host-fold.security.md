- **The MCP bearer no longer follows a host that only Unicode folding calls the same (#609, first half)** — `internal/mcp`'s `sameHost`, which decides whether a vault-resolved token rides a request, compared with `strings.EqualFold`. That folds by Unicode, and the Greek sigmas share a fold orbit while IDNA keeps them apart: `σ.example` and `ς.example` punycode to `xn--4xa.example` and `xn--3xa.example`, two names that can belong to two people. Calling them one origin sent the bearer to the second. Case folding a hostname is an ASCII operation and is now done that way, which is what `internal/egress` and `internal/vaultresolve` already did — this was the last of the three that did not. The trade is one-directional and deliberate: UTS46 folds U+212A (KELVIN SIGN) and U+017F (LONG S) onto `k` and `s`, so those pairs really are one domain and the token is now withheld from servers it was resolved for. A withheld bearer costs a 401; a wrongly-shared one costs the secret. No production path was reachable before the fix, because this repo's MCP clients refuse redirects. The issue's other half — that an environment's `networking.allowed_hosts` is never validated — stays open.
