- **Environment keys are refused in the reference's words** ([#840](https://github.com/OpenSDLC-Dev/managed-agent-platform/issues/840)) — A revoked environment key the platform minted now answers 401 `authentication_error` "OAuth access token has been revoked." on every public route, management routes included; an expired or unknown key keeps `invalid environment key`, as does a revoked pre-0021 key, whose operator-chosen value may be guessable. A live key sent as a Bearer to a management route, with no human credential beside it, gets the reference's recorded refusal: a 401 "Authentication failed" on `GET /v1/agents`, a 403 `permission_error` on `GET /v1/skills` and `GET /v1/skills/{id}`. The key no longer reads `GET /v1/skills/{id}`, so a dead key or any other Bearer there now gets `x-api-key header is required` instead of `invalid environment key`. A skill's versions, a version and its `/content`, all a worker reads, still serve it; other management routes keep the missing-key 401. Only a Bearer with the `sk-map-env01-` prefix is looked up there, so a management key's request costs no extra query. A key still goes with its deleted environment, a 401 where the reference's work stats answer 404; [docs/DIVERGENCES.md](docs/DIVERGENCES.md) says why.
