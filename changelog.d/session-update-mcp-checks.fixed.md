- **A session update checks MCP hosts and no longer needs a toolset per server** ([#1017](https://github.com/OpenSDLC-Dev/managed-agent-platform/issues/1017), [#1018](https://github.com/OpenSDLC-Dev/managed-agent-platform/issues/1018)) — `POST /v1/sessions/{id}` with `agent.mcp_servers` now refuses a host the environment's `limited` policy does not admit, with the 400 session create gives. It used to answer 200 and fail at the dial, so a client that relied on that must add the host to `allowed_hosts` or set `allow_mcp_servers=true`. The same route now accepts a patch that leaves a declared server with no `mcp_toolset`, where it used to answer 400. The reference's 200 was recorded on `rescheduling`; taking it on `idle` is an inference. So `agent.tools: []` works alone, and removes every tool, not only MCP's. The server stays declared and is still dialled, and a call already waiting on confirmation still runs. A later turn on a session with tool history sends those blocks with no `tools`, which the Messages API is expected to refuse; clearing both fields already did this. Agent create, agent update and session create keep the rule. [docs/DIVERGENCES.md](./docs/DIVERGENCES.md) records the evidence.
