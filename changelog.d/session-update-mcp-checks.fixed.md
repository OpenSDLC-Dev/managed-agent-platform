- **A session update's MCP checks follow the reference** ([#1017](https://github.com/OpenSDLC-Dev/managed-agent-platform/issues/1017), [#1018](https://github.com/OpenSDLC-Dev/managed-agent-platform/issues/1018)) — `POST /v1/sessions/{id}` with `agent.mcp_servers` now refuses a host the environment's `limited` policy does not admit, with the 400 session create gives. It used to answer 200 and fail at the dial, so a client that relied on that must add the host to `allowed_hosts` or set `allow_mcp_servers=true`. The same route now accepts a patch that leaves a declared server with no `mcp_toolset`, where it used to answer 400. So `agent.tools: []` works alone, and clears a session's MCP tools in one step. Such a server stays declared and is still dialled, and offers no tools. Later turns send any earlier tool blocks with no `tools`, as they already did after both fields were cleared. Agent create, agent update and session create keep the rule. [docs/DIVERGENCES.md](./docs/DIVERGENCES.md) records the evidence and what rests on inference.
