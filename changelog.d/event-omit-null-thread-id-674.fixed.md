- **Events omit a null `session_thread_id` or `deny_message` instead of rendering it (#674, part 1)** — No recorded reference event carries either key as `null`: it has a value or is left out. The events list, the stream and the `POST /v1/sessions/{id}/events` echo now match that on the types where the recordings show it: `session_thread_id` on the tool-use events, the inbound answers to them and `user.interrupt`, and `deny_message` on `user.tool_confirmation`. A cross-posted event still names its thread on the session view, and a denial's `deny_message` still renders. The change is made at render time, so stored payloads, including every existing row of the append-only log, are untouched. The Go SDK types both keys as nullable there and decodes a missing key to the same zero value, with `Valid()` false, that it gave the null.
