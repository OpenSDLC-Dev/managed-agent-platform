- **Events omit a null `session_thread_id` or `deny_message` instead of rendering it (#674, part 1)** — Every recorded reference event carries these keys with a value or leaves them out; none renders them as `null`. The events list, the stream and the `POST /v1/sessions/{id}/events` echo now match that. A cross-posted event still names its thread on the session view, and a denial's `deny_message` still renders. The echo also omits `processed_at` until the event is processed, as every recorded echo of an unprocessed event does; `user.define_outcome`, stamped only when its turn settles, therefore now echoes without the key. The list and the stream still render that null, which stays registered as a divergence. The change is made at render time: stored payloads, including every existing row of the append-only log, are untouched. The Go SDK decodes a missing key to the same zero value, with `Valid()` false, that it gave the null.
