- **A message posted while a model request is in flight is read after the reply that never saw it, and `processed_at` is stamped when an input is consumed** ([#793](https://github.com/OpenSDLC-Dev/managed-agent-platform/issues/793)) — A `user.message`, `user.define_outcome` or delivered `agent.thread_message_received` that lands mid-request now replays after that request's reply and tool results, where the next request consumed it, instead of merged ahead of the reply. After an `end_turn` reply the chained request used to end on the assistant's turn, a prefill that Claude 4.6 and later models reject with a 400 `invalid_request_error` (https://platform.claude.com/docs/en/api/errors, "Prefill not supported"), so the session idled on `retries_exhausted`; on other routes the model continued its own reply. Existing sessions replay in the new order on their next turn, at one prompt-cache miss. The grader's and dreams' transcripts use the same order. `processed_at` is now stamped when the request that consumes an input starts, 1 µs before its `span.model_request_start`, as the reference stamps it, rather than when the turn settles; `agent.thread_message_received` is null until then. The list and stream still show each event at its receipt position.
