- **A coordinator's all-settlement turns can no longer loop forever** — a delegated turn whose calls were all answered inside the settlement has nothing left to wait for, so it hands its own turn straight back; a model that keeps making such turns (a repeated `list_agents`, a `wait_for_agents` that keeps timing out) drove that with no delay and no bound. The thread never idled, so the session stayed `running` — archive and delete refused it — and because the queue serves the oldest turn first and a re-queue does not move it, the loop starved every other session's turn on a single-brain deployment. Twenty-five consecutive such turns now cut the chain: the thread idles on `end_turn` with a `session.error` of type `delegation_chain_exhausted_error` saying why, and a message resumes the work. Input arriving mid-turn still chains past the cap and resets the count, so a busy coordinator is unaffected. The thread wake paths also gained the unanswered-tool-call guard the API's message trigger already had. (#442)
