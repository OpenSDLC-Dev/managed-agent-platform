- **`make gcp-kms-role-check` holds each GCP identity's Cloud KMS role to the cipher calls in the code** ([#750](https://github.com/OpenSDLC-Dev/managed-agent-platform/issues/750)) — `tools/kmsrole` reads the key-level roles out of the Terraform under [deploy/gcp/](./deploy/gcp/) and every `Encrypt`/`Decrypt` site out of every package each `cmd/` binary transitively imports, and fails when an identity is granted less than its binary calls. It runs in CI beside the other `gcp-*` checks, outside `make verify` because the Go gate does not depend on the GCP tree; `go run ./tools/kmsrole` prints the table it derived. This closes the mechanism behind #748, where the executor's role said Encrypter while its code had decrypted for three tagged releases — nothing went red, because the cipher's startup probe only encrypts, so both processes went Ready and the deploy was green while every private-repository clone and vault-credentialed MCP dial lost its credential. It is a floor, not a split: it never asks for a role to be narrowed. Anything it cannot read honestly it refuses rather than guesses — an unknown role, a member it cannot match to a binary, a conditional or counted grant, an override file, a module, grants split across two Terraform roots.
