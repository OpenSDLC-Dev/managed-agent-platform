- **The model gateway runs in compose and on Helm** (plan 59 slice 2) — the compose stack starts `modelgateway` on `localhost:8090` (`MODELGATEWAY_PORT`), sharing the control plane's OpenBao transit key and loopback bind. The Helm chart renders it under `modelgateway.enabled`: two replicas the scheduler prefers to spread across nodes, a ClusterIP Service on 8090 and a PodDisruptionBudget of `maxUnavailable: 1` that never holds a pod that is not Ready, its own ServiceAccount, the release's database, bootstrap key, cipher and `identity.*`. With a chart-managed Secret and no credential cipher the render fails, because the gateway does not start without one. Releases publish a `modelgateway` image beside the other three, from the same build. `deploy/gcp/` gains the gateway's service account in `foundation/` and, in `environment/`, its Workload Identity binding, `roles/cloudkms.cryptoKeyEncrypterDecrypter` on the credential key and `roles/cloudsql.client`; an existing deployment applies `foundation/` before `environment/`, whose data source reads the new account.
