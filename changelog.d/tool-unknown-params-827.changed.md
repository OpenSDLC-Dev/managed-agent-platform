- **Sandbox tools refuse input they do not understand, and `grep` lists files by default and searches as ripgrep does** ([#827](https://github.com/OpenSDLC-Dev/managed-agent-platform/issues/827)) — `bash`, `read`, `write`, `edit`, `glob` and `grep` answer an input property their schema does not declare with a tool error naming it and listing the ones they accept. They used to drop it and run anyway, so a `grep` sent `-i` searched case-sensitively without saying so. This holds on the executor and the BYOC worker, on Anthropic- and OpenAI-protocol routes alike; the OpenAI adapter still strips `additionalProperties` from the schemas. A `grep` call with no `output_mode` now returns the paths of matching files, the reference's default, where it used to return `path:line:text` lines; ask for `"output_mode": "content"` to get those. And `grep` is now ripgrep rather than the image's GNU grep: its pattern is Rust regex syntax, not PCRE; it skips hidden files, binary files under a directory, and what a git repository's `.gitignore` names, and no longer skips `node_modules` otherwise; and it lists in path order.
