- **Sandbox tools refuse input they do not understand, and `grep` lists files by default and searches as ripgrep does** ([#827](https://github.com/OpenSDLC-Dev/managed-agent-platform/issues/827)) — `bash`, `read`, `write`, `edit`, `glob` and `grep` answer an input property their schema does not declare with a tool error naming it and the ones they accept, where they used to drop it and run anyway — so a `grep` sent `-i` searched case-sensitively without saying so. This holds on the executor and the BYOC worker, on Anthropic- and OpenAI-protocol routes alike. A `grep` with no `output_mode` now returns the matching files' paths, the reference's default, not `path:line:text` lines; `"output_mode": "content"` gives those. And `grep` is ripgrep now, not the image's GNU grep: Rust regex syntax, not PCRE; hidden files searched but `.git` and five other version-control directories skipped, as are binary files under a directory, what a git repository's `.gitignore` names and the memory sync's own files (unless a path names them), and `node_modules` no longer skipped otherwise; answers list in path order, which costs rg its parallel search. **Upgrade BYOC workers with the platform**: an older worker drops the new options and answers `path:line:text`, a newer one under an older platform answers paths where the model was promised lines, and the work protocol carries no worker version to catch either.
