- **A session's file copy is deleted like any other row; rolling back below migration 0046 is unsupported** ([#856](https://github.com/OpenSDLC-Dev/managed-agent-platform/issues/856)) — Migration 0047 drops the copy-delete guard and tombstone trigger 0046 added for older binaries, and `map.copy_delete` with them; the reference count on the object-delete queue stays. **Upgrading** from a release before 0046 (v0.4.0 or earlier): roll the brain and executor first, then the control plane, and create no session that mounts a file until the rollout finishes. A failed `helm upgrade --atomic` is a rollback too. While an older replica overlaps, its executor's harvest deletes a live session's copies, so `resources[]` names a missing file that no provision mounts; its session delete, file delete and expiry sweep delete copies, leaving no orphan rows, but owe each copy's own key rather than the object it shares, so an object whose last name was that copy stays in storage, owed by nothing; and a create can deadlock against its session delete. #578's entry lists what else an older replica does.
