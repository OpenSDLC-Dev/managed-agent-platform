- **Plan 30 archived — console-issued environment keys accepted against the real `ant` CLI** ([#43](https://github.com/OpenSDLC-Dev/managed-agent-platform/issues/43), [docs/plan/30_environment-keys-console-issuance.md](docs/plan/30_environment-keys-console-issuance.md)) — the issue's acceptance was "an operator can issue and rotate an environment key, and a real `ant beta:worker` authenticates with it end to end (no manual DB edits)", and that is what ran: a key issued by curl against the console API drove a real `ant beta:worker poll` built from the read-only CLI checkout, confirmed positively rather than by silence — the platform's own `…/work/stats` reported a non-zero `workers_polling`, which only an authenticated poll can produce, while answering 401 to the management key, so the worker lane is demonstrably the lane in play. Revoking through the console returned a bodiless 204 and the running `ant` process printed the platform's `authentication_error` envelope and exited. The property the retired rotate-on-mint model could never offer was proven directly: two named keys, two real workers, revoke one — that host's process exited on the auth error while the other kept polling with a still-valid key and a still-empty log. Zero database access at any point. The full transcript, including why the run used its own throwaway control plane rather than the shared compose stack, is in [docs/HISTORY.md](docs/HISTORY.md). One step of the plan's own stronger wording — polling *until an item is pulled* — is deferred to [#363](https://github.com/OpenSDLC-Dev/managed-agent-platform/issues/363) and says so: `queue.Poll` serves `tool_exec` only, which the brain enqueues after a model turn, so it needs the live model route that STATE.md has been tracking as a blocker all along; what it would newly prove is the CLI's tool-runner half, not the queue path, which is already pinned over real HTTP by test.
