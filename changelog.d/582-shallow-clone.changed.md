- **A mounted repository is now a shallow clone in the reference's shape** ([#582](https://github.com/OpenSDLC-Dev/managed-agent-platform/issues/582), plan 63) — the executor cloned a `github_repository` with its full history, every tag and one remote, and the default-branch and commit forms with every branch. Every checkout form now fetches one commit at depth 1 with no tags: the default branch's, a branch's, or a commit's, which is fetched by its exact SHA. A repository with a long history therefore costs far less of the clone's byte budget and time. The default-branch and commit forms no longer carry the other branches, so checking one out needs a `git fetch` first, with a credential for a private repository; `git fetch --unshallow` brings back history the same way. A commit can now be any commit in the repository's fork network, because GitHub serves those by SHA through the repository's own URL, where the full clone found only commits its branches and tags reach; an app that takes a SHA from an untrusted source should check it first. A branch name git's ref-name rules refuse, such as one with `*`, is refused before the remote is asked, still with reason `checkout`, as is a commit the remote does not have. The `.git/config` takes the shape recorded inside a reference sandbox: remotes `origin` and `github` at the URL's `.git` spelling, both fetching every branch, `gh-resolved = base` on `github`, and `gc.auto = 0`.
