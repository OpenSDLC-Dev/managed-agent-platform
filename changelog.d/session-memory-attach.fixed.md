- **Memory-store attachment: three recorded mismatches fixed, and the rules around them made explicit** ([#666](https://github.com/OpenSDLC-Dev/managed-agent-platform/issues/666), [#668](https://github.com/OpenSDLC-Dev/managed-agent-platform/issues/668), [#671](https://github.com/OpenSDLC-Dev/managed-agent-platform/issues/671)) — Matching the recorded reference: two stores whose names slug alike both attach, the later at `-2`, where the create (and every fire of a deployment carrying the pair) failed with a 400; a name with no letters or digits mounts at `/mnt/memory/memstore-<id token, lowercased>`; the element omits `instructions` when none was supplied instead of rendering `null`. Our own rules, not recorded: past a pair, each store keeps its own slug and the others take the first free `-3`, `-4`, …, cut to fit the 255-byte NAME_MAX; and a well-formed memory store id naming no store is a 404 `not_found_error` on session and dream create (it was a 400), inferred from the reference's 404s for absent ids. An archived store stays a 400. The `instructions` and mount-path changes are forward-only: a session keeps the elements stored at its create.
