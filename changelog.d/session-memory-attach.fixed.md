- **Attaching memory stores at session create answers as the reference does** ([#666](https://github.com/OpenSDLC-Dev/managed-agent-platform/issues/666), [#668](https://github.com/OpenSDLC-Dev/managed-agent-platform/issues/668), [#671](https://github.com/OpenSDLC-Dev/managed-agent-platform/issues/671)) — An unknown store is a 404 `not_found_error`, not a 400; an archived one stays a 400. Stores whose names slug alike no longer fail the create: the first in request order mounts at the slug and each later one at the first free `-2`, `-3`, …, which also un-breaks a deployment carrying such a pair, whose every fire failed. A name with no letters or digits mounts at the slug of the whole store id, `/mnt/memory/memstore-<token, lowercased>`, not the bare token. The element omits `instructions` when none was supplied instead of rendering `null`. The last two are forward-only: a session re-serves the elements it stored at create, so one created before this release keeps its `"instructions": null` and an all-symbol store's old mount path.
