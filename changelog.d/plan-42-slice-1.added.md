- **Multi-tenant activation, slice 1 — the workspace registry and scope on every request** (plan 42, [docs/plan/42_multi-tenant-activation.md](./docs/plan/42_multi-tenant-activation.md), [#56](https://github.com/OpenSDLC-Dev/managed-agent-platform/issues/56)): a `workspaces` table lands, seeded with the `default` row every existing deployment already runs in — recognised, not created, so a populated database is untouched. Every credential now resolves exactly one `org_id`/`workspace_id`/`project_id` scope — a management key, an environment key, a sessions token, a gate token, and a human identity alike — and `anthropic-organization-id` / `anthropic-workspace-id` are stamped wherever a credential resolved a scope, 200 or 4xx, absent on a pre-auth 401 and on the two header rejections. The `anthropic-workspace-id` request header may only narrow to a workspace the credential covers: absent with several candidates is 400, naming the ambiguity; malformed is 400 and unrecognized-or-uncovered is 404, both bodies verbatim from the reference. A credential bound to an archived workspace is refused as an unknown one. Two new identity variables, `IDENTITY_CLAIM_WORKSPACES` and `IDENTITY_WORKSPACE_MAP`, mirror the existing role-claim pair; unconfigured with more than one live workspace fails closed rather than guessing. `EnsureAPIKey` now moves a value re-configured into a second workspace, loudly. No read-side enforcement yet — a later slice.
