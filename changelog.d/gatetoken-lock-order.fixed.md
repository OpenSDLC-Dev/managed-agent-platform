- **Deleting a session while its gate re-mints no longer deadlocks** — The two paths took the session row and its gate-token rows in opposite orders, so a delete racing a re-mint closed a lock cycle and Postgres aborted whichever side it picked: a 500 from the delete, or a failed gate provisioning, at random between the two. Minting now takes the session row first, the order the delete already took, so the race resolves rather than aborting. It also settles who loses it, which was previously the coin toss: the delete wins and the re-mint fails against a session that is gone, the same outcome the cycle produced whenever the delete happened to be the survivor. Both were already retryable and neither could corrupt anything; what changes is that one of them stops happening (#313).
