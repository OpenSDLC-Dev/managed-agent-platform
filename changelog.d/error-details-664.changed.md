- **Error bodies carry the reference's `details` member where it was recorded** ([#664](https://github.com/OpenSDLC-Dev/managed-agent-platform/issues/664)) — Some errors now nest a `details` object inside `error`, with the keys and values recorded against the reference: `GET /v1/files/{id}/content` on an upload (`error_code: file_not_downloadable`), an environment update that changes its kind (`error_code: invalid_config_type_change`), and the work heartbeat's 412 (`error_code: heartbeat_precondition_failed`, `error_visibility: user_facing`, and `current_state` — the item's state and last heartbeat, the beat's TTL, `lease_extended: false` and `lease_updated_at`). On the console namespace, the 404s for an unknown environment, environment key, workspace or API key carry `error_visibility: user_facing`, and the environment's also `error_code: environment_not_found`. Every other error renders byte for byte as before, and no message changes. A heartbeat whose `expected_last_heartbeat` is not a timestamp now answers 404 rather than 412 when the work item does not exist. What still differs is registered in [docs/DIVERGENCES.md](docs/DIVERGENCES.md).
