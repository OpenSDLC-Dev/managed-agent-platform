- **Error bodies carry the reference's `details` member where it was recorded** ([#664](https://github.com/OpenSDLC-Dev/managed-agent-platform/issues/664)) — Some errors now nest a `details` object inside `error`, with the recorded keys and values: `GET /v1/files/{id}/content` on an upload (`error_code: file_not_downloadable`), an environment update that changes its kind (`error_code: invalid_config_type_change`), and the work heartbeat's 412 (`error_code: heartbeat_precondition_failed`, `error_visibility: user_facing`, and `current_state`, the item as the refused beat found it). On the console namespace the 404s for an unknown environment, environment key, workspace or API key carry `error_visibility: user_facing`, the environment's with `error_code: environment_not_found`. **A malformed id there is now a 400 `invalid_request_error`, not a 404**, as recorded, with a message of ours: one missing its prefix or carrying bytes that cannot be stored. A UUID is a well-formed environment key id, and an API key update reports an unknown key before it judges the body. Messages of the errors that already existed do not change, and every other error renders byte for byte as before. A heartbeat whose `expected_last_heartbeat` is not a timestamp now answers 404 rather than 412 when the work item does not exist. What still differs is registered in [docs/DIVERGENCES.md](docs/DIVERGENCES.md).
