- **A `bash` tool call that its own `set -e` ends keeps what it changed** ([#938](https://github.com/OpenSDLC-Dev/managed-agent-platform/pull/938)) — on bash 5, a command that turned on `set -e` and then failed lost the call's changes: the next call ran from the state before it, without the call's directory, exports or errexit. The failed call also printed `local: can only be used in a function` on its stderr, and bash 5.2 added `pop_var_context`. The template now sources the command at the top level, not inside a function, so the save runs with its variables intact. One effect follows: `local` outside a function now fails in a command, as it does in any bash script.
