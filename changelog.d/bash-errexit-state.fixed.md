- **A `bash` tool call that its own `set -e` ends keeps what it changed** ([#938](https://github.com/OpenSDLC-Dev/managed-agent-platform/pull/938)) — on bash 5, a command that turned on `set -e` and then failed lost the call's changes: the next call ran from the state before it, without the call's directory, exports or errexit. The failed call also printed `local: can only be used in a function` on its stderr, and on bash 5.2 `pop_var_context: head of shell_variables not a function context` as well. The template now sources the command at the top level, not inside a function, so the save runs with its variables intact. Bash still prints its own `pop_var_context` line when `set -e` fires inside a `.` or `eval` within the command's own function, but the call keeps its state. A command's ERR trap also no longer fires on the template's own line when the call exits with a nonzero status.
