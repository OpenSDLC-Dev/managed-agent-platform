- **A work item's `started_at` is stamped when it enters the queue, as the reference stamps it (#542)** — The work API rendered `started_at` null until a worker's first heartbeat, and cleared it again on every poll hand-out. The reference sets it on a freshly enqueued item still `queued`, re-stamps it when an item re-enters the queue, and leaves it untouched through poll, ack, heartbeat and stop. The 2026-09-19 self-hosted recordings show this for 11 enqueues and 2 re-queues, on `ant` 1.10.0 and 1.34.0. Enqueue now stamps it, and a poll that reclaims a dead worker's `starting` or `active` item stamps it afresh. Heartbeats no longer touch it, so a polled or acked item renders a timestamp where it used to render null. No client this project knows of reads the field. A queued item enqueued before the upgrade takes its `created_at` at its next hand-out. Nothing else is backfilled.
