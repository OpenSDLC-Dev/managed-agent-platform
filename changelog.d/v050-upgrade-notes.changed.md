- **Upgrading from v0.4.0 applies migrations 0041–0047 in one transaction, which holds each table lock it takes until it commits** — The first v0.5.0 controlplane, brain or executor to start runs all seven. It takes `sessions`, `session_threads`, `deployment_runs`, `work_session_tokens`, `files` and `deleted_sessions` ACCESS EXCLUSIVE, so every read and write of those tables, from any replica, waits until the run commits. How long that is grows with two tables: 0041 validates its CHECK over every `session_threads` row, and 0046 builds three indexes on `files`, measured under 0.4 seconds per million rows. 0043, 0045, 0046 and 0047 give up a lock they cannot have within 2 seconds; 0041 and 0042 set no such bound. A give-up or a deadlock rolls the whole run back and starts it again, up to five attempts, which adds up to about 85 seconds of those waits and the back-off between them before the start exits with the error; the next start tries again.
