- **A deployment run keeps its `session_id` after the session is deleted** ([#663](https://github.com/OpenSDLC-Dev/managed-agent-platform/issues/663)) — Deleting a fired session used to null its run's `session_id`, so the run rendered `session_id` and `error` both null, against the published rule that exactly one is non-null. The run now keeps the id, as the reference's does, even though `GET /v1/sessions/{id}` answers 404 for it; `has_error=false` and a schedule's `last_run_at` still count the run as a success. Migration 0042 drops the foreign key on `deployment_runs.session_id`. The change is forward-only: a run whose session was deleted before the upgrade has already lost the id, which is recorded nowhere, so it keeps rendering `session_id: null`.
