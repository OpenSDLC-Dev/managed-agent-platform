- **The six sandbox tools' schemas are closed, as the reference's were recorded** ([#822](https://github.com/OpenSDLC-Dev/managed-agent-platform/issues/822)) — `bash`, `read`, `write`, `edit`, `glob` and `grep` now carry `"additionalProperties": false`, and `edit`'s `old_string` carries `"minLength": 1`, two keywords a 2026-09-02 recording showed the reference handing the model. The Anthropic-protocol adapter sends them; the OpenAI-protocol adapter strips both from every built-in tool, as it does the web tools' keywords since [#682](https://github.com/OpenSDLC-Dev/managed-agent-platform/issues/682). The tools run as before: edit already refused an empty `old_string`. The request does change: an Anthropic-protocol route in front of a backend that refuses these keywords (vLLM's `/v1/messages`, or a gateway in front of Gemini) now rejects the tool list of any agent with a built-in tool enabled, where turning the web tools off used to keep them out. Other recorded differences stay on purpose, registered in [docs/DIVERGENCES.md](docs/DIVERGENCES.md): `bash`'s `restart` and `timeout_ms` and `edit`'s `replace_all`, from the SDK's typed inputs; relative `file_path`s, which the skills block relies on; `read`'s `view_range`; and five tools' descriptions, ours. `grep` took the reference's properties and description, and every sandbox tool now refuses a property it does not know ([#827](https://github.com/OpenSDLC-Dev/managed-agent-platform/issues/827)).
