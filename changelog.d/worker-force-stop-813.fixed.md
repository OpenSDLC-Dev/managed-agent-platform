- **The worker force-stops work whose heartbeat is refused or whose lease is not extended, as the SDK worker does** ([#813](https://github.com/OpenSDLC-Dev/managed-agent-platform/issues/813)) — when a heartbeat answers `lease_extended: false` beside a live state, or fails with a `4xx` other than `412`, `408`, `409` and `429` (a `404` for work that is gone, a `401` or `403` for a refused key), the bundled worker now cancels the run and force-stops the work item, as the reference Go SDK worker does. It used to release the item without a stop. A `412` (now even one that arrives as the run finishes) and transient failures that outlast the lease's TTL release it unstopped. A force stop that fails in turn is only logged; under a revoked key the next poll is refused too, and the worker exits on it as before. When such a refusal comes before any beat has extended the lease, the worker now backs off before its next poll as it does after a failed poll (up to 1 s, doubling per such item to 60 s), because the control plane re-queues the session's unanswered calls on that stop; the SDK worker polls again at once. A stop the control plane asks for is not followed by one. A heartbeat answered `409` is now retried, as the SDK worker retries it, instead of ending the run.
