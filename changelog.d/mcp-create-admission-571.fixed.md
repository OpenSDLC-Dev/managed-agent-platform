- **A session whose MCP server its environment blocks is refused at create, as the reference refuses it (#571)** — Such a session used to be created and start running. It then emitted a `session.error` on every work cycle, because the platform checked a `limited` environment's networking only when dialling the server. `POST /v1/sessions` now answers 400 `invalid_request_error` with the reference's recorded message, which names each blocked server and host: `MCP server host(s) blocked by environment network policy: "<name>" (<host>). Add these hosts to the environment's allowed_hosts, or set allow_mcp_servers=true.` The session is never created. `allowed_hosts`, including a `*.` wildcard, and `allow_mcp_servers` admit a server as they did at dial time. A `self_hosted` environment, which has no networking, and an `unrestricted` one admit every server. A deployment run that hits the check now settles on `mcp_egress_blocked_error`, and a scheduled fire pauses the deployment. The dial-time check stays, because an agent's `mcp_servers` can change mid-session. **Upgrade note:** a create that used to succeed on such an environment now fails, and a scheduled deployment whose agent declares such a server pauses on its first fire after the upgrade; add the host to `allowed_hosts` or set the flag, then unpause it.
