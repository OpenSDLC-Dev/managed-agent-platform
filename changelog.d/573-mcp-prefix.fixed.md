- **A custom tool can no longer be named in the `mcp__` frame an MCP tool is offered under** ([#573](https://github.com/OpenSDLC-Dev/managed-agent-platform/issues/573)) — an agent create whose `tools[]` holds a `custom` tool named, say, `mcp__deepwiki__ask_question` now answers 400 `invalid_request_error` `tools.1.custom.name: custom tool name "mcp__deepwiki__ask_question" uses reserved MCP tool prefix`, as the reference was recorded answering. An agent update answers the same under `agent.`. Such a name used to be stored, and the brain then gave it to the custom tool and dropped the MCP tool it shadowed. An agent stored with one keeps resolving, and the brain still settles that contest by declaration order. It does the same for a session's tools, which are not checked, whether set by an override at create or by a mid-session `agent.tools` update. The 64-byte ceiling on a composed MCP tool name is unchanged; #573 stays open for it.
