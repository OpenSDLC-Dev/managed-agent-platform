- **A custom tool can no longer be named in the `mcp__` frame an MCP tool is offered under** ([#573](https://github.com/OpenSDLC-Dev/managed-agent-platform/issues/573)) — an agent create whose `tools[]` holds a `custom` tool named, say, `mcp__deepwiki__ask_question` now answers 400 `invalid_request_error` `tools.1.custom.name: custom tool name "mcp__deepwiki__ask_question" uses reserved MCP tool prefix`, as the reference was recorded answering. The other routes that take `tools[]` from a request refuse it too, in the same words under their own path: `agent.` on an agent update and on a mid-session `agent.tools` update, and `agent.agent_with_overrides.config.` on a session create's override. Such a name used to be stored, and the brain then gave it to the custom tool and dropped the MCP tool it shadowed, wherever `tools[]` listed the two. An agent or a session stored with one keeps resolving that way. The 64-byte ceiling on a composed MCP tool name stays, by decision: a tool whose composed name is longer is still not offered, and docs/DIVERGENCES.md registers that as a deliberate divergence.
