- **A repository's checkout survives an image startup that ends the probe's shell** ([#941](https://github.com/OpenSDLC-Dev/managed-agent-platform/pull/941)) — before the tools run, the executor asks whether each mounted repository's `.git` is in the sandbox, and clones it only when it is not. The probe read an exit of 1 as the `.git` not being there. An image's startup can end the probe's shell first with 1, such as a `set -e` startup whose command failed. The executor then cloned again, and the extraction could replace the checkout, the agent's edits with it. The probe now reads only the answer its own script printed, as the file mounts' probe does. A startup that ends the shell first leaves it unanswered, and the executor asks through the file API instead. On Kubernetes that read's exit status no longer answers either, unless the startup also printed past the output cap.
