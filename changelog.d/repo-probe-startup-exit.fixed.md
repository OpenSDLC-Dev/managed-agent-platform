- **A repository's checkout survives an image startup that ends the probe's shell** ([#941](https://github.com/OpenSDLC-Dev/managed-agent-platform/pull/941)) — before the tools run, the executor asks whether each mounted repository's `.git` is in the sandbox, and clones it only when it is not. The probe read an exit of 1 as the `.git` not being there. An image's startup that ended the probe's shell first with 1, such as a `set -e` startup whose command failed, therefore made the executor clone again, and the extraction replaced the checkout with the agent's edits in it. The probe now reads only the answer its own script printed, as the file mounts' probe does. A startup that ends the shell first leaves it unanswered, and the executor asks through the file API instead. On Kubernetes that read no longer takes such a startup's exit status as an answer either: a file read the startup ends reports an error, not a missing file.
