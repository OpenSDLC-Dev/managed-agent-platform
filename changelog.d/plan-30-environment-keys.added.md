- **Plan 30 drafted — console-issued environment keys** ([docs/plan/30_environment-keys-console-issuance.md](docs/plan/30_environment-keys-console-issuance.md), [#43](https://github.com/OpenSDLC-Dev/managed-agent-platform/issues/43)) — the design for the operator surface that issues BYOC worker credentials, which `EnsureEnvironmentKey` has never had: a self-hosted operator has had to seed a key into Postgres by hand. The plan settles the model on the reference console's, observed live on 2026-08-10 down to its request and response bodies: many **named** keys per environment, each shown exactly once at issue, individually revocable, expiring a year out — retiring the one-live-key-per-environment invariant migration 0013 introduced. Issuance stays **off the wire**, on a namespace that mirrors the reference console's own private API path-for-path (`/api/oauth/organizations/{organization_id}/environments/{environment_id}/tokens…`) rather than inventing one, so `/v1` stays byte-identical to the reference and future console-facing endpoints have a convention to follow instead of a naming debate. Four divergences from that dialect are deliberate and reasoned in the plan: our own key prefix (never mint an Anthropic-look-alike credential), prefixed row ids, no copied `authorization_details` (the reference's claim is narrower than what the key actually authorizes, and we neither generate nor enforce it), and the house error envelope. Three slices follow: storage and primitives, the endpoints, then docs and a real `ant beta:worker` acceptance run.
