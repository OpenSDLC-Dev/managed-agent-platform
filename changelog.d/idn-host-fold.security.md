- **An IDN alias no longer passes as the ASCII host it folds to (#606)** — `egress.NormalizeHost` folded case by Unicode, which maps several non-ASCII letters onto ASCII ones: `gİthub.com` (U+0130) normalized to `github.com`, so the gate admitted it and the substitution engine — which selects a vault credential through the same matcher — handed it that host's secret, while Go's HTTP stack resolved the request through IDNA to `xn--github-qyd.com`, a name anyone may register. Case folding a hostname is an ASCII operation, and it is now done that way, matching `internal/vaultresolve`'s `lowerHost` and `internal/mcp`'s `sameHost`. Nothing legitimate narrows: `ValidateHostEntry` already accepts only ASCII labels, so every entry on the matching side — an operator's `allowed_hosts`, a credential's, `WEBTOOL_ALLOWED_DOMAINS`, the curated registry set — was ASCII already, and only a non-ASCII *request* host stops matching. The defect predated the thirty-host registry set, but that set is what made `github.com` reachable without an operator listing it, so the two land together.
