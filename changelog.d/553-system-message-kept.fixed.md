- **A `system.message` stays accepted on every model, by decision** ([#553](https://github.com/OpenSDLC-Dev/managed-agent-platform/issues/553)) — the reference turns the event into a mid-conversation `role: "system"` message, which only some models accept. On Claude Haiku 4.5, it was recorded refusing a lone `system.message` on those grounds, with `400 invalid_request_error`. This platform refuses that lone send too, by the SDK's rule that the event comes last and follows a `user.message` or a tool result. It accepts a send that keeps the rule on every model. Whether the reference refuses such a send on Claude Haiku 4.5 is unrecorded. This platform appends the event's text to the system prompt, which needs no support for mid-conversation system messages. So the model reads the text ahead of the whole conversation, not at its place in it. [docs/DIVERGENCES.md](./docs/DIVERGENCES.md) records the three reasons and what the reference was recorded doing.
