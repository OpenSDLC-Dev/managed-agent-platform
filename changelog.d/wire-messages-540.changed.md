- **Error messages are the reference's own wherever a recording holds them** ([#540](https://github.com/OpenSDLC-Dev/managed-agent-platform/issues/540)) — An error this platform raises for a condition the reference was recorded refusing now carries the reference's `message` verbatim, ids and values in place: a stale agent `version` answers `Concurrent modification detected. Please fetch the latest version and retry.`, an unknown body field `Failed to parse request body: unknown field "x"`, an unknown path `Not found`, an unsupported method `Method Not Allowed`, a missing environment `Environment env_… not found.`, and so on across agents, environments, sessions, events, resources, deployments, vaults, files, memory stores, skills, the work API and the console namespace. A deployment run's `error.message` takes the reference's run sentences where recorded (`session creation rejected: …`), not the session create's. Status codes, error types and `details` do not change; a few checks now run in the reference's order, so a request gets the refusal it was recorded getting. Errors no recording reaches keep their wording. Detail a verbatim message drops that only the server knew moves to an Info log line with the request id — the stale-version 409's expected and current versions among them. A client matching our old wording must match the new; the console matches on status. What still differs is in [docs/DIVERGENCES.md](docs/DIVERGENCES.md).
