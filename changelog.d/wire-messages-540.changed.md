- **Error messages are the reference's own wherever a recording holds them** ([#540](https://github.com/OpenSDLC-Dev/managed-agent-platform/issues/540)) — An error this platform raises for a condition the reference was recorded refusing now carries the reference's `message` verbatim, ids and values in place: a stale agent `version` answers `Concurrent modification detected. Please fetch the latest version and retry.`, an unknown body field `Failed to parse request body: unknown field "x"`, an unknown path `Not found`, a missing environment `Environment env_… not found.`, and so on across every resource, the work API and the console namespace; a deployment run's `error.message` takes the reference's run sentences where recorded. Status codes, error types and `details` do not change; a few checks now run in the reference's order. An error no recording reaches keeps its wording unless it shares a helper with a recorded one — the unknown-field sentence reaches every strictly decoded body, the unknown-path and unsupported-method ones every route — and [docs/DIVERGENCES.md](docs/DIVERGENCES.md) lists each such extension. A client matching our old wording must match the new; the console matches on status. **Upgrade self-hosted workers before or with the control plane:** an older worker misreads an archived memory store's new refusal as one file's, so each file it pushes there stays un-synced, even after an unarchive, until its content changes.
