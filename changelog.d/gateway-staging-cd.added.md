- **GCP staging's CD follows the model gateway switch** ([#909](https://github.com/OpenSDLC-Dev/managed-agent-platform/pull/909), part of [#906](https://github.com/OpenSDLC-Dev/managed-agent-platform/issues/906)) — `deploy.yml` reads whether the gateway runs off the chart's render of `staging-values.yaml`, before the build. While it runs, the workflow requires a twelfth repository variable, `MODELGATEWAY_SERVICE_ACCOUNT`, annotates and reads back the gateway's ServiceAccount, and expects a fourth Cloud SQL proxy, and `mode2-secret.sh` requires `brain-api-key` in place of `model-providers.json`, refusing a key the control plane or the gateway would refuse at startup. Either mode carries the other's key when Secret Manager has it, so an `--atomic` rollback across the switch finds its own. `mode2-secret.sh` now requires `MODELGATEWAY=true|false`: a hand run must say which. `staging-values.yaml` still turns the gateway off, so staging deploys as before.
