- **MCP servers authenticate with the session's vault credentials — plan 29 slice 5a (#45)** — A session whose attached vaults hold an `mcp_oauth` or `static_bearer` credential for a server its agent declares now dials that server with the token as `Authorization: Bearer`, on both paths that dial: discovery and the tool call. Matching is by URL after the reference's normalization, the first vault with a match wins, and a server no credential matches is dialled with no credential of this platform's choosing — an `mcp_servers` URL written with userinfo still authenticates with the Basic header net/http derives from it, and a matched token replaces that header rather than joining it. Credentials are resolved on every dial with no cache, so a rotation or an archive reaches the next one without a restart. **A refused credential is now reported as one.** A 401 or 403 from the server — its refusal, or its requiring a credential where none matched — is `mcp_authentication_failed_error` rather than `mcp_connection_failed_error`, as is a credential this platform could not open, whose dial is not made at all rather than quietly downgraded to an anonymous one the operator believes was authenticated. A failure of the *lookup* is neither: it says nothing about the credential, so the work item faults and the call is retried rather than answered permanently. The status is watched in this platform's own transport chain because the go-sdk carries it only as prose. Every other failure is unchanged. OAuth refresh of an expired `mcp_oauth` token is the next slice.
