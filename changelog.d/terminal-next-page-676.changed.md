- **A list's last page omits `next_page` on most routes, as the reference's does** ([#676](https://github.com/OpenSDLC-Dev/managed-agent-platform/issues/676)) — Every list used to send `"next_page": null` when no page followed. The reference answers this two ways, by route, and now so does this platform: files, skills, skill versions, environments and an environment's work keep the explicit null, while every other list sends `next_page` only when a further page exists. The sessions list likewise sends `prev_page` only when there is a page before it, never as null. The typed SDK's pagers, the `ant` CLI and the console treat an absent key and a null alike, as the end of the list; a client that tests for the key's presence must accept both. The per-route evidence, and the lists whose rule is inferred, are in [docs/DIVERGENCES.md](docs/DIVERGENCES.md).
