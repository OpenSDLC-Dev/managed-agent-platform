- **A CI guard could report a miss for the very thing it matched, or pass over what it found** ([#763](https://github.com/OpenSDLC-Dev/managed-agent-platform/issues/763)) — under `pipefail` a pipeline reports its rightmost non-zero status, and `grep -q` exits on its first match. That closes the pipe under a writer still writing, which takes SIGPIPE and carries the pipeline to 141. Which way that fails depends on how the verdict is consumed: with `|| { … exit 1; }` the step reddens for the condition it was checking for; with `&& { … exit 1; }` the 141 skips the failure branch, so the step **passes although the forbidden thing was found** — three such sites existed, latent only because their blocks set no `pipefail`. It surfaced on macOS, whose pipe buffer starts at 16 KB, on a 22 KB `helm template` render; Linux holds 65,536 bytes. Eighty-two pipeline stages now read to EOF — eighty greps, and two `awk` programs whose bare `exit` left the render unread — and `make pipes-test` refuses the shape before it can come back. Which readers count was measured on a 5 MB writer rather than reasoned: `grep -q`/`--quiet`/`-m`, `head` and `sed`'s `q` take the writer down on GNU and BSD alike; `awk`'s bare `exit` does so on mawk, gawk and one-true-awk, while `exit 1` and `END { … }` do not; and `grep -L` does so on neither grep, so it is not named however plainly it reads as an early exit.
