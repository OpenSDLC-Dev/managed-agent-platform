- **The model gateway speaks OpenAI's Chat Completions** (plan 59 slice 4) — `POST /v1/chat/completions`, also under `/openai`, passes through to each vendor's OpenAI-compatible endpoint with the same routing, fallback, limits and usage ledger as the Messages routes, the answer under the model name the caller sent. Streams are asked for their usage, so every one is counted, and the usage chunk reaches only a caller that asked for it. `/v1/models` answers in OpenAI's shape on `/openai`, and at the root for a request without `anthropic-version`, listing every alias a key may use; errors on these routes use OpenAI's envelope. A request setting what a vendor ignores although the answer depends on it — `parallel_tool_calls: false` on DeepSeek and MiniMax, and MiniMax's `stop` and forced `tool_choice` — goes to the model's other deployments, or is refused naming the field, as is MiniMax's `disable_parallel_tool_use` on the Messages routes. The live tier drives all of it with openai-go.
