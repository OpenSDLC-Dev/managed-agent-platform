- **On Docker, skills and memory stores materialize under a read-only root filesystem** ([#859](https://github.com/OpenSDLC-Dev/managed-agent-platform/issues/859)) — with `SANDBOX_READONLY_ROOTFS=true`, every bulk write failed with `container rootfs is marked read-only`, so no skill and no memory store reached a Docker sandbox. Each was logged and skipped, and the agent ran without it. The daemon refuses an archive extracted at a directory outside the writable mounts, and the bulk write extracted every batch at `/`, even when every file was bound for `/workspace`, `/tmp` or `/mnt`. A batch is now extracted inside the mount it is bound for: one request per mount it touches, so still one for a whole skill. A path outside the writable mounts still fails, as a single write there does. Kubernetes was not affected.
