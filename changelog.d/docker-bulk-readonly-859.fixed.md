- **On Docker, skills and memory stores materialize under a read-only root filesystem** ([#859](https://github.com/OpenSDLC-Dev/managed-agent-platform/issues/859)) — with `SANDBOX_READONLY_ROOTFS=true`, every bulk write failed with `container rootfs is marked read-only`, so no skill and no memory store reached a Docker sandbox; each was logged and skipped, and the agent ran without it. The daemon refuses an archive extracted at a directory outside the writable mounts, and the bulk write extracted every batch at `/`. Under a read-only root a batch is now extracted a directory at a time, each archive at the directory its files land in, so the daemon checks every one as it checks a single write's, and a symlink the sandbox made pointing out of the mounts is refused rather than followed. That is a request per distinct directory plus one for the bookkeeping — a 61-file skill in 10 directories takes 11 — where a writable root still takes two. A batch whose delivery is refused, or whose directory cannot be made, now fails with the single write's errors (not writable, is a directory) rather than the raw daemon or `tar` message — on Kubernetes too.
