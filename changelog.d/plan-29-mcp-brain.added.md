- **An agent's MCP tools reach the model — plan 29 slice 4b (#45)** — An `mcp_toolset` expanded to nothing at request assembly; it now expands to the tools its server reported. The brain reads the session's catalog, offers each enabled tool as a model tool definition, commits a call on one as `agent.mcp_tool_use`, and schedules the MCP driver that answers it — which is the half slice 4a shipped ahead of this one so a rollout could not strand a call. **The model sees `mcp__{server}__{tool}`; the wire never does.** The reference's own protocol carries a call's server in a field of its own, so the name it shows the model is bare — but this brain assembles one flat `tools[]` for an ordinary Messages endpoint, which has no such field, and two servers offering `search` would be two definitions under one name. So the prefix is ours and forced by architecture rather than chosen, it exists only inside a provider request, the event carries the bare `name` and `mcp_server_name` exactly as the SDK types them, and replay puts the two back together — because the assistant `tool_use` block this log re-sends on every later turn has to name a tool that turn's request actually offers. **A tool can be declared and not offered, and that costs one tool rather than the turn.** A Messages tool name must match `^[a-zA-Z0-9_-]{1,64}$` — documented in one place, the tool-use guide's parameter table, and in neither the API reference nor the SDK types — while an MCP server may have a 255-character name and 128-character tools, so a pair legal on both wires composes into a name the endpoint would reject, and it would reject the whole request, every turn, on a log that keeps replaying the same agent. That tool is dropped, and so is one whose prefixed name the agent's own `tools[]` already took (the author's definition wins over a third party's listing), one a server reported twice, and every tool of a server whose listing failed. A `configs[]` entry naming a tool the server does not report is the fifth, and the only one the docs settle — a warning, never an error, because an MCP server's tool list is unknowable when the agent is written. All five are log lines: no wire event describes one, `session.error` names connection and authentication failures and this is neither, and the brain's skills and mounted-file injection already put an unresolvable reference in the log rather than on the session stream. Plan 29 proposed a `system.message` and that is corrected here — the event is client-sent, carries a documented placement rule, and replays into the *system prompt*, so one per turn would grow the prompt without bound. **A turn waits for a listing it has never had.** An `mcp_toolset` whose server has no catalog row is not assembled at all: no model call, the item is handed straight back as MCP work, and the discovery driver chains the turn once the listing is in — one round trip per session, and the alternative silently misses the agent's whole reason for declaring the server on its first turn. A *failed* row is an answer rather than an absence, so the turn runs without that server's tools instead of suspending to re-dial an endpoint that just refused, which would loop for as long as the server stayed down; every failed server is re-attempted whenever any discovery pass runs. A row written for an endpoint the agent no longer declares counts as no row, behind the mid-session patch that already deletes such rows in its own transaction. **An MCP call gates like any other ask tool**, since `always_ask` is the MCP toolset's documented default: the intent carries `evaluated_permission`, the turn idles with `requires_action` naming it, and the confirmation resume's MCP arm — shipped a slice early — is live. A turn's platform calls now enqueue one work item of the highest kind they demand, `mcp_exec` over `web_exec` over `tool_exec`, each driver answering its own family and chaining the next. Request assembly and call classification became one resolution rather than two passes over the same `tools[]`, which is what makes "what the model was offered" and "what a name it called back means" incapable of disagreeing.
