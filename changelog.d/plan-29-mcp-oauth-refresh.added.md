- **An expired MCP OAuth token refreshes at the dial — plan 29 slice 5b (#45)** — An `mcp_oauth` credential whose `expires_at` has passed, or is within a minute of passing, performs the RFC 6749 refresh-token grant against its stored token endpoint before the MCP server is dialled, and the rotated tokens are sealed back onto the credential so the next dial — in this session or another — starts from them. The exchange's wire shape now lives in one place, `internal/oauthrefresh`, shared with the `mcp_oauth_validate` probe that already performed it. A credential that cannot refresh sends the token it has and lets the server answer, which is the reference's documented no-refresh-token behaviour. An issuer that refuses the grant is `mcp_authentication_failed_error`; one that is unreachable or answers 429 or 5xx is neither, so the work item retries rather than answering a failure that says nothing about the credential. The token endpoint is dialled through the same address guard and no-redirect rule as every other credential-supplied URL.
