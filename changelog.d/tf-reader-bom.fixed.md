- **A UTF-8 BOM hid a `.tf` file's first block from both readers** ([#765](https://github.com/OpenSDLC-Dev/managed-agent-platform/issues/765)) — a block header is anchored with `^\s*`, which matches no BOM, so the header on a file's first line went unseen behind one and `make gcp-split-check` and `make gcp-kms-role-check` reported success over it. Terraform parses such a file — `terraform fmt -check` reports formatting drift and no diagnostic — so refusing it would reject configuration the binary accepts, and both readers now drop a leading BOM on decode. Only the first one: a second, or one further into the file, is an `Invalid character` to Terraform and glues to the header behind it the same way, so both readers refuse that instead, while still reading the three positions Terraform accepts one in — inside a string, a comment and a heredoc body.
