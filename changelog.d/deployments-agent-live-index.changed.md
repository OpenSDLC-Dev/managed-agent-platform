- **Archiving an agent no longer sorts its live deployments to name the ones blocking it** — The refusal that lists the deployments pinning an agent had only an `agent_id` index behind it, so it sorted its matches and returned to the table to test `archived_at`. A new partial index carries the seek, the predicate and the ordering together, and the read becomes index-only. It runs while the archive holds a row lock the agent's deployment creates and repins queue behind, so the saving is theirs as much as the archive's. The bound is unchanged and is not the point: counting the blockers reads every one of them whatever index serves it, so this is the cost of each read rather than how it grows (#523).
