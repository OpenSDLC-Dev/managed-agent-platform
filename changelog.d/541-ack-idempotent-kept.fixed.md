- **A repeat work ack keeps its 200, by decision** ([#541](https://github.com/OpenSDLC-Dev/managed-agent-platform/issues/541)) — the reference answers an ack of an item that is no longer queued with `409 invalid_request_error`. This platform still answers it 200 with the item unchanged. The SDK client retries an ack whose response was lost, and the SDK's poller, which the `ant` worker runs, force-stops any item whose ack fails. So a 409 would turn one lost response into a stopped item and a second hand-out. Every re-hand-out takes a fresh work id, so a repeat ack cannot come from a worker that lost the item, and the first heartbeat still decides who owns it. [docs/DIVERGENCES.md](./docs/DIVERGENCES.md) records the three reasons and what the reference was recorded doing.
