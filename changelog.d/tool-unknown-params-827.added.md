- **`grep` takes the reference's twelve search options and its description, and runs ripgrep in the sandbox** ([#827](https://github.com/OpenSDLC-Dev/managed-agent-platform/issues/827)) — The built-in `grep` tool's schema and description are the ones a 2026-09-02 recording showed the reference handing the model: `output_mode` (`files_with_matches`, `content`, `count`), `-i`, `-n`, `-A`, `-B`, `-C`/`context`, `type`, `glob`, `head_limit`, `offset` and `multiline`, each passed to ripgrep as the flag its description names. The executor and the BYOC worker carry a static ripgrep 15.2.0 for Linux x86_64 and aarch64 and install it in a sandbox's `/tmp` the first time it greps there, so `grep` behaves the same on glibc, musl and busybox images. That `/tmp` must be writable and allow executing files; where ripgrep cannot run, `grep` is a tool error saying why. From source, `make ripgrep` fetches the pinned binaries — `make test`, `make eval`, the release targets and the Dockerfile run it — and a build made without it logs a warning at startup and its `grep` reports that it carries none. The worker tarballs and the server image ship [NOTICE](./NOTICE), [LICENSE](./LICENSE) and [THIRD_PARTY_LICENSES](./THIRD_PARTY_LICENSES), the license texts of what that ripgrep links.
