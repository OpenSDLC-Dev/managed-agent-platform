- **`grep` takes the reference's twelve search options, and runs ripgrep in the sandbox** ([#827](https://github.com/OpenSDLC-Dev/managed-agent-platform/issues/827)) — The built-in `grep` tool's schema is the one a 2026-09-02 recording showed the reference handing the model: `output_mode` (`files_with_matches`, `content`, `count`), `-i`, `-n`, `-A`, `-B`, `-C`/`context`, `type`, `glob`, `head_limit`, `offset` and `multiline`, each passed to ripgrep as the flag its description names. The executor and the BYOC worker carry a static ripgrep 15.2.0 for Linux x86_64 and aarch64 and install it in a sandbox's `/tmp` the first time it greps there, so `grep` behaves the same on glibc, musl and busybox images and the image needs no grep of its own. The sandbox's `/tmp` must be writable and allow executing files; where ripgrep cannot run, `grep` is a tool error saying why. Building from source, `make ripgrep` fetches the pinned binaries — `make test`, `make eval`, the release targets and the Dockerfile run it — and a plain `go build` without it makes binaries whose `grep` reports that they carry none. [NOTICE](./NOTICE) carries ripgrep's license.
