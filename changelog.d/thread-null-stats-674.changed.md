- **A session thread's `stats` and `usage` are `null` until its first status transition** ([#674](https://github.com/OpenSDLC-Dev/managed-agent-platform/issues/674), part 3) — The thread list, get and archive responses rendered both as objects from birth. A primary thread that has never run now renders both `null`, as the reference does, and a thread born running (a spawned child, or the primary of a session created with `initial_events`) renders both from birth. Migration 0045 adds a `transitioned` flag to `session_threads`, set by a thread's first status change and on every existing thread, so a thread created before the upgrade keeps rendering objects even if it never ran. The spec holds `usage` back until the first idle; the recordings show it beside `stats` from the first transition, and this follows the recordings (docs/DIVERGENCES.md). **Deploy order:** a client that reads either field as an object breaks on `null`, the first-party console among them, so roll out a console release carrying [managed-agent-console#184](https://github.com/OpenSDLC-Dev/managed-agent-console/pull/184) before this release. During a rolling upgrade an earlier-build replica sets no flag: a never-run primary reads as objects from it and `null` from an upgraded one, and an idle primary it both starts and stops without a model request settling usage renders `null` until its next transition.
