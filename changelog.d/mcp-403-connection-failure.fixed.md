- **An MCP server answering 403 is now a connection failure, not a refused credential** — A dial the server answered `403 Forbidden` raised `mcp_authentication_failed_error` on the session's error event, sending an operator after a credential that was fine. It raises `mcp_connection_failed_error`, which is what a recording of the reference answers: five servers dialled in one turn returned an authentication failure for 401 alone, with 403, 407, 500 and 502 all reported as connection failures. Only the classification changes — the call still answers the model with an `is_error` result so the turn carries on, and the event still carries `retry_status: retrying`, which the same recording confirms the reference sends for both types (#572).
