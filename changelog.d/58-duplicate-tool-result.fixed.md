- **A tool result for a call that already has one is accepted and dropped** ([#58](https://github.com/OpenSDLC-Dev/managed-agent-platform/issues/58)) — `POST /v1/sessions/{id}/events` used to refuse a `user.tool_result` or `user.custom_tool_result` for an answered call with 400 "already has a result". It now answers 200 and appends nothing, and a send that carried nothing else answers `{"data":[]}`, as the reference was recorded answering both a byte-identical re-delivery and a changed result. A worker or SDK runner that re-sends a result after losing the response no longer reports a result that landed as failed. In a send that carries other events too, only the repeat is dropped, and a `system.message` that follows a repeat is refused 400, as the reference refuses it. Two results for one call in one request are no longer refused: for an unanswered call the first is stored and the response echoes both, and for an answered one the send is the same no-op. An unknown id and a kind mismatch are still refused. The BYOC worker no longer re-reads the log after a refused result: paired with an older control plane, it faults the pass on such a late answer and recovers on the next reclaim.
