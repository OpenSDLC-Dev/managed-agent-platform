- **A repository clone that the git host fails partway names the host** ([#940](https://github.com/OpenSDLC-Dev/managed-agent-platform/issues/940)) — a failed clone's `github_repository_clone_error` carries a reason saying whose fault it was. Some of the host's failures read as the caller's or this platform's. An empty pack response, or one cut after its headers, read `checkout`: go-git takes it for "already up to date", and the checkout then misses the commit. A pack response whose framing breaks read `internal`. So did the host's own messages: an `ERR` line, a message on the sideband's error band, and a `NAK` with no pack. So did a response that go-git's pack response or sideband decoder refuses, and a pack band that carries no pack. Each of these now reads `network`. The executor's log names the host's failure. A pack that is corrupt past its signature keeps its reason. An unknown commit still reads `checkout`, and the reasons `auth`, `not_found` and `too_large` are unchanged. A ref advertisement whose `ERR` line, or text that is not git's, quotes the clone's deadline as it passes now reads `network`; it read `timeout`.
