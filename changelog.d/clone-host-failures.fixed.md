- **A repository clone that the git host fails partway names the host** ([#940](https://github.com/OpenSDLC-Dev/managed-agent-platform/issues/940)) — a failed clone's `github_repository_clone_error` carries a reason saying whose fault it was. Some of the host's failures read as the caller's or this platform's. An empty pack response, or one cut after its headers, read `checkout`: go-git takes it for "already up to date", and the checkout then misses the commit. A pack response whose framing breaks read `internal`. So did the host's own messages: an `ERR` line, a message on the sideband's error band, and a `NAK` with no pack. So did a response that go-git's pack response or sideband decoder refuses, and a pack band that carries no pack. Each of these now reads `network`. The clone's HTTP transport records the host's transport failures. Where a recorded failure decides the reason, the executor's log names it. A pack that is corrupt past its signature keeps its reason. An unknown commit still reads `checkout`, and the reasons `auth`, `not_found`, `too_large` and `timeout` are unchanged.
