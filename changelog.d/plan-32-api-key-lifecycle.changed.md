- **Management API keys gain a lifecycle: status, expiry and a masked hint** ([docs/plan/32_management-api-keys.md](docs/plan/32_management-api-keys.md) slice 1, [#378](https://github.com/OpenSDLC-Dev/managed-agent-platform/issues/378)) — `api_keys` has held one live credential per logical name since the first migration, rotated only by restarting the control plane with a new `CONTROLPLANE_API_KEY`. Migration 0024 gives it the model the reference implements, recorded live against the real console on 2026-08-13 rather than inferred: a `status` of `active` · `inactive` · `archived` replaces the binary `revoked_at`, which is dropped once its revoked rows become archived ones — so a key can now be **disabled reversibly**, which a revocation timestamp could not express, and "delete" is an archive that leaves the row readable. The fourth state the reference reports, `expired`, is deliberately **not stored**: it is computed from the new nullable `expires_at` inside the authentication query, against the database's own clock, so a lapsed key stops working the instant it lapses and there is no sweeper that could be down when it does — and no clock-skewed replica that could lengthen a credential's life. Existing rows are grandfathered rather than backfilled, for the reason plan 30 gave when environment keys took expiry: dating an expiry from `created_at` would retro-expire the credential a deployment is authenticating with right now. `partial_key_hint` records the masked value a listing will show, because a SHA-256 cannot be un-hashed and it is the only part of a key that survives issuance, and `created_by` records who issued one — with no foreign key, so a principal removed from the IdP does not take working credentials with them, which is the rule the reference states outright. The one-live-per-name invariant is **narrowed rather than dropped**: the reference allows two live keys to share a name (verified by creating two and watching both stay active), but `EnsureAPIKey` still needs the guarantee to rotate safely against concurrent replicas, so the index now covers exactly the rows nobody issued — keyed on the semantics rather than on the literal name `bootstrap`, so the schema does not depend on a string constant living in `cmd/controlplane`. One operator-visible rule comes with it, ahead of the console surface that will make it reachable: naming a value in `CONTROLPLANE_API_KEY` makes that key **env-var-managed, whatever it was before**. If the value already exists as a key someone issued, the row is adopted — losing its issuer and any expiry it carried, because a bootstrap key that kept either would sit outside the one-live index or would be refused by the very query that just reported success. Adoption is deliberate rather than an error, since refusing to boot would strand the control plane behind a state only a direct database edit could clear, and would protect nobody: setting the variable at all takes the deployment access that could configure a fresh value instead. It is not silent, though — this runs once at startup, so it logs a warning naming the previous issuer and status, which is the only way an operator who pasted an archived key out of an old runbook would ever learn they had brought it back. A first-time key stays quiet. Otherwise nothing observable changes for an existing deployment: no route is added or altered in this slice, and the same `x-api-key` keeps working.
