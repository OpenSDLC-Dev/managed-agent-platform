- **A BYOC work item for a session with memory stores carries its sessions token** (plan 36 slice 5, [#52](https://github.com/OpenSDLC-Dev/managed-agent-platform/issues/52)). The poll response of an item whose session attaches a memory store now renders `secret` as the reference worker's envelope, `base64url(JSON {"sessions_token": "wtk_…"})` — a per-item token minted in the claim's own transaction (a token insert that fails leaves the item unclaimed), hashed at rest (migration 0030, `internal/worktoken`), and null on every other path and for every other item. The token is the worker's credential for that item, where the v1.66.0 reference worker sends it: the item's own heartbeat and stop, its own session's read and events, the skill reads, and the memory routes of the stores its session attaches, whose writes are the session's versions; a sibling session or an unattached store is not found, everything else refused, and the environment key is refused on the memory routes. It lives as long as the item — a re-hand-out, a lapsed lease, a stop or an archive ends it. Behavior-neutral until slice 6 lifts the `self_hosted` attachment refusal; the reference worker's own per-item flow (`EnvironmentWorker.HandleItem`) is exercised against the in-process server in a test, which adds `github.com/creack/pty` as a test-only indirect dependency. Two registry entries ([docs/DIVERGENCES.md](./docs/DIVERGENCES.md)); #165 re-scoped to the same envelope.
