- **A failed repository clone blames the git host only for the host's own failures** ([#939](https://github.com/OpenSDLC-Dev/managed-agent-platform/pull/939)) — the `session.error` reason of a failed clone named the host, as `network`, for faults that were this platform's own: a key service that refused the token's decrypt, a database connection lost while the sealed token was read, a full disk under the executor's clone spool (including one whose error quoted a file named `EOF`), or an executor out of file descriptors or ports. A key service that stalled read as `timeout`. All of these now read as `internal`. Two more misreadings are fixed: an HTTP/2 stream that the host reset, or a connection it shut down, partway through the fetch read as `internal` and now reads as `network`; and the clone's deadline passing while the pack was requested read as `internal` and now reads as `timeout`.
