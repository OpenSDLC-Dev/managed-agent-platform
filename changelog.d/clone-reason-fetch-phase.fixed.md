- **A repository clone blames the git host only for a failed fetch** ([#939](https://github.com/OpenSDLC-Dev/managed-agent-platform/pull/939)) — the `session.error` reason of a failed clone named the host, as `network`, for faults that were this platform's own: a key service that refused the token's decrypt, a database connection lost while the sealed token was read, or a full disk under the executor's clone spool. These now read as `internal`. A failed clone also no longer leaves its tar, up to the clone's byte budget, in the session's `/tmp` when the upload breaks off or the extraction never starts; the sandbox was swept only after a cancellation.
