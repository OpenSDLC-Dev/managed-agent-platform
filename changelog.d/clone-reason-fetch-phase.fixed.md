- **A failed repository clone blames the git host only for the host's own failures** ([#939](https://github.com/OpenSDLC-Dev/managed-agent-platform/pull/939)) — the `session.error` reason of a failed clone named the host, as `network`, for faults that were this platform's own: a key service that refused or dropped the connection for the token's decrypt, a database connection lost while the sealed token was read, a full disk under the executor's clone spool (including one whose error quoted a file named `EOF`), or an executor that could not create a socket or assign a port. A key service that stalled read as `timeout`. All of these now read as `internal`. Some of the host's failures read as `internal`, and now read as `network`: an HTTP/2 stream the host reset or a connection it shut down partway through the fetch, a pack response that is not git's, a read of the pack response that the kernel timed out, and a message the host sent on its error band. The clone's own deadline passing while the pack was requested or read now reads as `timeout`, where it read as `internal`.
