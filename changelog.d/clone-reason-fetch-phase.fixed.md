- **A failed repository clone blames the git host only for the host's own failures** ([#939](https://github.com/OpenSDLC-Dev/managed-agent-platform/pull/939)) — the `session.error` reason of a failed clone named the host, as `network`, for faults that were this platform's own: a key service that refused the token's decrypt, a database connection lost while the sealed token was read, or a full disk under the executor's clone spool, including one whose error quoted a file named `EOF`. A key service that stalled read as `timeout`. All of these now read as `internal`. In the other direction, an HTTP/2 stream that the host reset partway through the fetch read as `internal`, and now reads as `network`. A failed clone also no longer leaves its tar, up to the clone's byte budget, in the session's `/tmp` when the upload breaks off or the extraction never starts: the sandbox was swept only after a cancellation. The sweep now removes the tar alone, so it can no longer delete a directory at that path that was not the platform's, or the staging directory of an extraction that is still running.
