- **A failed repository clone blames the git host only for the host's own failures** ([#939](https://github.com/OpenSDLC-Dev/managed-agent-platform/pull/939)) — the `session.error` reason of a failed clone named the host, as `network`, for some of this platform's own faults. Among them were a key service that refused or dropped the connection for the token's decrypt, and a database connection lost while the sealed token was read. Others were a full disk under the executor's clone spool, an executor out of descriptors, memory, buffers or ports, and a path go-git refuses to check out whose name quotes a network error, such as `EOF`. A key service that stalled read as `timeout`. All of these now read as `internal`. Some of the host's failures read as `internal`, and now read as `network`. These are an HTTP/2 stream the host reset or a connection it shut down while the pack response arrived, an empty ref advertisement, a pack response that is not git's, and a read of the pack response that a transport error ended. The clone's own deadline passing while the pack was requested or read now reads as `timeout`, where it read as `internal`.
