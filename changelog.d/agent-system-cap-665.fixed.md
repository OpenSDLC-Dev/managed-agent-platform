- **An agent's own `system` is capped at 100,000 characters (#665)** — `POST /v1/agents` and `POST /v1/agents/{id}` now refuse a longer system prompt with 400 `invalid_request_error`, as the reference does; until now only a session's `agent_with_overrides` replacement was bounded. Characters are Unicode code points, the unit the reference was recorded using. The check joins the whole-spec caps every resolved agent answers to, so an agent already stored over the limit now also fails session create (directly or as a coordinator's roster member), agent updates that leave its prompt in place, and `agent.tools`/`agent.mcp_servers` updates on sessions that already carry it — the consequence #66 and #287 accepted for the tools and `mcp_servers` caps. An update that shortens or clears `system` repairs such an agent; meanwhile a session can still use it through an override that replaces or clears `system`.
