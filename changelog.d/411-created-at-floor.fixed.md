- **Each new event is stamped after the one before it, whatever the database clock does** ([#411](https://github.com/OpenSDLC-Dev/managed-agent-platform/issues/411)) — an event's `created_at` came from the database clock alone. A clock that stepped backwards, as an NTP correction or a VM resuming after host sleep can make it, could date a later event before an earlier one. The `created_at[…]` filters on `GET /v1/sessions/{id}/events` compare against that stamp, so a poll could list an earlier event and then never list a later one. Each append is now stamped at least one microsecond past the session's last event. A healthy clock is already past that floor, so nothing changes there; while the clock is behind, each append advances one microsecond until it catches up. Events written by one append can still share a stamp.
