- **Each append is stamped after the one before it, whatever the database clock does** ([#411](https://github.com/OpenSDLC-Dev/managed-agent-platform/issues/411)) — an event's `created_at` came from the database clock alone, read row by row. A clock that stepped backwards, as an NTP correction or a VM resuming after host sleep can make it, could date a later event before an earlier one. The `created_at[…]` filters on `GET /v1/sessions/{id}/events` compare against that stamp, so a poll could list an earlier event and then never list a later one. Each append is now stamped once, when it holds the session's lock and at least one microsecond past the session's last event, and its events share that stamp. A healthy clock is already past that floor, which then never binds; while the clock is behind, each append advances one microsecond until it catches up. A client whose bound is an event's `processed_at` still depends on the appending host's clock agreeing with the database's. A spawned thread, listed in creation order, is floored past the session's newest thread the same way, and an approval wait that would read negative is no longer recorded.
