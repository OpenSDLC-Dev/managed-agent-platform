- **The kind image fixture no longer requires an import record that `kind load` did not leave** ([#1025](https://github.com/OpenSDLC-Dev/managed-agent-platform/issues/1025)) — `TestHookedImagesOfParallelPackagesAreTheirOwn` failed on every local `make verify` against kind v0.30.0 on node image v1.34.0. That setup leaves only the image's tag, not the `import-<date>@sha256:<digest>` record, so the test reported the record as missing. CI's kind v0.33.0 on node image v1.37.0 leaves both and passed. `sandboxtest.LoadIntoKind` now lists the nodes' images after loading an archive that has an `index.json`. Where no node holds an import record of any load, the load is handled as one whose record cannot be named, the path an archive without `index.json` already takes, and `go test -v` logs why. Where any node holds one, the load must still hold its own record on every node, `Remove` still takes it off, and where only another load's record keeps the check on, the log of a failing test names it. `LoadIntoKind` now registers that removal itself, before it lists the nodes, so the removal is still attempted when the listing fails.
