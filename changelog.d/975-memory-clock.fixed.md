- **A memory's `created_at` and `updated_at` are the time it was written** ([#975](https://github.com/OpenSDLC-Dev/managed-agent-platform/issues/975)) — the memories API and a session's memory sync now stamp a memory with the database's `statement_timestamp()`, the start of its insert or update, which comes after the store lock. They used to take the column default `now()`, which Postgres freezes when the transaction begins. So a create that waited on the store lock listed behind memories committed while it waited, and every memory one sync created shared one `created_at` and listed in random id order. The memories list now follows the order the creates committed, as far as the database clock keeps time, and so agrees with the memory-versions list. At create the two stamps are one reading, so they are equal, as on the reference. The gap between a memory's stamp and its head version's `created_at` shrinks from a lock wait to the time between two statements. A dream's clone of its input store keeps `now()`, so its memories still share one `created_at`, and the list breaks that tie on `id`.
