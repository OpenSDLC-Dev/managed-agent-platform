- **Console SSO and RBAC, proven end to end and archived** ([docs/plan/31_console-sso-rbac.md](docs/plan/31_console-sso-rbac.md) slice 6, [#56](https://github.com/OpenSDLC-Dev/managed-agent-platform/issues/56)) — the plan's acceptance criterion, run against the shipped `deploy/compose` stack with `--profile iam` on a database Casdoor had never seeded, with no manual database edits: every operator action an HTTP call, and the only processes touching Postgres the control plane and Casdoor themselves. A **real** token, minted the way a console mints one — the seeded application carries `authorization_code` and `refresh_token` and deliberately no password grant, so the run scripts the full authorization-code + PKCE exchange against Casdoor's own OP endpoints rather than taking a shortcut that would have proven a path nobody uses. Both tokens decode as the platform requires: `iss` byte-equal to the configured issuer, `aud` the application's client id, and `groups` spelled `organization/name`. The chain then runs in one direction and holds at every step: `x-api-key` still answers **200** with the identity lane fully configured (the promise every slice made, and the one a regression would be quietest about); an admin token creates an agent and an environment; a viewer token is refused both with **403** `permission_error` "this route requires the developer role" while the same token reads at **200**, so it is the role and not the authentication that separates them; a viewer is refused the console key surface; an admin issues an environment key over it; and **`ant` 1.21.0**, built from the read-only reference checkout, long-polls that environment with the key and is never refused — then a forged key and, after `POST …/revoke`, that same real key are both **401** `authentication_error`, through the CLI and on a direct call alike. One Casdoor mechanic is recorded in [docs/HISTORY.md](docs/HISTORY.md) because no struct would have revealed it: its login handler reads the OAuth parameters from the **query string** while the credentials ride the JSON body, and sending everything in the body answers `Grant_type:  is not supported in this application` — an empty grant type read from a query string that carried nothing, which reads like a misconfigured application and is not one. **Slice 5 did not ship and was not invented.** The api-key issuance surface is gated in the plan on a live observation of the reference console's key-management dialect, which needs an authenticated console account and creates real credentials in it; the observation could not be made, so the plan's own provision applied and the slice moved to [#378](https://github.com/OpenSDLC-Dev/managed-agent-platform/issues/378) carrying the recording it needs. Plan 31 archives on what it shipped.
