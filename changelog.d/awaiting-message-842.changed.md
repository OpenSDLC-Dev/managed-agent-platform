- **A message sent while the session rests on a tool response is refused** ([#842](https://github.com/OpenSDLC-Dev/managed-agent-platform/issues/842)) — A `user.message` or `user.define_outcome` posted while the primary thread is idle awaiting a custom tool's result, a self-hosted worker's result or a tool confirmation is now a 400 in the reference's words — ``Invalid user.message event at events[0]: waiting on responses to events [sevt_…]; only `user.tool_confirmation`, … may be sent`` — where it used to be queued behind the call. The send's own answers count first, wherever they sit in it, and so does an interrupt: a message beside the results that free the session, or behind the documented interrupt-and-redirect, is read as before, and one sent while the primary is still running queues as before. A client that sent a message to a session waiting on a call must now answer the call, or interrupt, first; a client such as the console receives the 400. [docs/DIVERGENCES.md](docs/DIVERGENCES.md) says which waits beyond a custom call's are inferred.
