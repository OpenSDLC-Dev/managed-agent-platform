- **A message sent while the session waits on a tool response is refused** ([#842](https://github.com/OpenSDLC-Dev/managed-agent-platform/issues/842)) — A `user.message` or `user.define_outcome` posted while the primary thread still waits on a custom tool's result, a self-hosted worker's result or a tool confirmation is now a 400 in the reference's words — ``Invalid user.message event at events[0]: waiting on responses to events [sevt_…]; only `user.tool_confirmation`, … may be sent`` — where it used to be queued behind the call. The send's own answers count first, wherever they sit in it, and so does an interrupt: a message beside the results that free the session, or behind the documented interrupt-and-redirect, is read as before. A client that queued a message while a call was pending must now answer the call, or interrupt, first; the console's composer stays enabled in that state and shows the refusal. [docs/DIVERGENCES.md](docs/DIVERGENCES.md) says which waits beyond a custom call's are inferred.
