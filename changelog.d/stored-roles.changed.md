- **Stored human roles, with no read-only tier (plan 69 slice 1)** — The control plane and gateway operator lane now use stored `user`, `developer` and `admin` roles. First unmatched sign-in gets user, which reaches only setup-code redemption. Reads and vault-credential writes require developer; memory redaction, API-key administration and environment-key administration stay admin-only. `IDENTITY_ROLE_MAP` is optional in both identity modes and applies on every verified request. Legacy `viewer` mappings now give user and lose read access: map readers to developer, which can also write. Older unexpired tokens can reapply their old mapped role. Deactivated principals stay refused. Principal DELETE and TRUNCATE now fail; replace retention DELETE jobs with the deactivated-row scrub in [the security guide](./docs/self-hosted-security.md#8-principal-retention). Existing management keys remain unchanged in this slice. Releases are held until plan 69 slice 7.
