- **Plan 36 drafted — memory stores** ([docs/plan/36_memory-stores.md](docs/plan/36_memory-stores.md), [#52](https://github.com/OpenSDLC-Dev/managed-agent-platform/issues/52)) — the design for the last v1 non-goal still on the roadmap: a workspace-scoped **memory store** attached through `resources[]`, mounted at `/mnt/memory/<slug>` and read and written with the ordinary file tools, every write an immutable, attributed **memory version**. Ground truth is the official memory and self-hosted guides plus `anthropic-sdk-go` read at the pinned tag (every memory type is already there) and, for the sync protocol, the reference worker's own implementation at v1.66.0. Key decisions: three Postgres tables and no blob; the id-less attachment element the reference's type dictates; materialization the files pattern sources from the store, with sync-back at the end of every tool run around the results transaction — the store wins conflicts under a compare-and-set, `read_only` is a file-tool guardrail as on the reference's worker; a per-work-item **sessions token** rendered in the poll response's `secret` for sessions with stores, because the reference's worker fails an item with stores and no token; the platform's BYOC worker runs the same sync over the wire. Eight slices, the first an SDK bump to v1.66.0; dreams, webhooks and version pruning are excluded and named. The plan is `draft`.
