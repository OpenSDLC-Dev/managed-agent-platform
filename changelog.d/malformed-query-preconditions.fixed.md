- **A query string that does not parse is refused rather than half-read** — Go's query parser silently drops a pair it cannot decode (`%zz`, or a pair holding a bare `;`) and, past Go's default ceiling of 10,000 pairs (GODEBUG `urlmaxqueryparams`), the whole query, so such a parameter used to read as never sent: `DELETE /v1/memory_stores/{id}/memories/{mid}` deleted without its `expected_content_sha256` precondition, `GET /v1/agents/{id}?version=1%zz` served the latest version, and the agent, session, session-event, deployment, deployment-run, dream, skill, file, memory-store, memory and memory-version lists answered with everything their filter should have excluded. Those routes, and the thread-event list that shares the session-event list's handler, now answer 400 `invalid_request_error` ("malformed query string: …"); every other route reads its query as before. The SDK and the `ant` CLI encode every pair they send, so they meet the 400 only past the ceiling — 10,000 `types[]` values on the session-event list, say — where such a list used to answer unfiltered. The reference's own answer is unrecorded ([#78](https://github.com/OpenSDLC-Dev/managed-agent-platform/issues/78)).
