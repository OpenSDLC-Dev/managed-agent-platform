- **A query string that does not parse is refused rather than half-read** — Go's query parser silently drops a pair it cannot decode (`%zz`, or a pair holding a bare `;`) and, past 10,000 pairs, the whole query, so such a parameter used to read as never sent: `DELETE /v1/memory_stores/{id}/memories/{mid}` deleted without its `expected_content_sha256` precondition, `GET /v1/agents/{id}?version=` served the latest version, and the agent, session, session- and thread-event, deployment, deployment-run, dream, skill, file, memory-store, memory and memory-version lists answered with everything their filter should have excluded. Those routes now answer 400 `invalid_request_error` ("malformed query string: …"). Routes whose parameters lose nothing a caller relies on when dropped — paging, a view, `include_archived`, the work API's knobs — still read the query as before. SDK and `ant` CLI requests are unaffected, since they always encode their queries.
