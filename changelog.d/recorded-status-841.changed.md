- **Six refusals answer the reference's recorded status** ([#841](https://github.com/OpenSDLC-Dev/managed-agent-platform/issues/841)) — Where a recording shows the reference answering with another status than ours, this platform now follows it, in its words: an agent path id that is not an agent id (`/v1/agents/undefined`) is 400 `Invalid agent ID.` on all four agent routes, not 404, while the reference's own id format reaches the 404 an absent agent gets; a thread path id that is not a thread id (`sth_…`) is 400 `Invalid thread ID: …`, not 404; a work id with none of the reference's prefixes (`POST …/work/poll`) is 400 `Invalid work ID format: …` on every work-item route, not 404; a `user.interrupt` naming a thread that is not this session's is 404 `Thread not found: …`, not 400; an environment delete the sessions block is 409 `Environment has N active sessions. Use force=true to delete anyway.` with `x-should-retry: false`, not 400 — forced, the same 409 in our words, since `force=true` still deletes no session here; and a session's memory store id with the right prefix but a token outside our id alphabet reaches the recorded 404, not a 400. A client keyed on the old statuses must follow; the console branches on none of them. [docs/DIVERGENCES.md](docs/DIVERGENCES.md) names the routes that take a recorded answer unrecorded.
