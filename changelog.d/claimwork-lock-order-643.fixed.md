- **A worker's poll no longer deadlocks against a session delete or interrupt** ([#643](https://github.com/OpenSDLC-Dev/managed-agent-platform/issues/643)) — A worker's poll racing the delete of, or a `user.interrupt` to, a `self_hosted` session with a memory store attached could fail one of the two with a 500. Migration 0043 drops the foreign key from `work_session_tokens` to `sessions`; a trigger on `sessions` deletes a session's tokens with it, whatever deletes the row, a replica still on the previous build included. The migration holds `work_session_tokens` and `sessions` exclusively until its run commits and waits at most 2 seconds for each; reads of `sessions` queue behind it while it waits or holds them. A lock cycle with an old replica during a rolling upgrade aborts the migration, not live traffic, and an autovacuum on either table, unless it is preventing wraparound, is cancelled rather than waited out while `deadlock_timeout` is under 2 seconds, as its 1s default is. Every migration run now retries a lock timeout or deadlock, up to five attempts over about 15 seconds, and each retry re-applies all pending migrations, since they share one transaction. A start whose attempts all fail exits with the error, and the next start tries again.
