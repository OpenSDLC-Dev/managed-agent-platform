- **A worker's poll no longer deadlocks against a session delete or interrupt** ([#643](https://github.com/OpenSDLC-Dev/managed-agent-platform/issues/643)) — For a `self_hosted` session with a memory store attached, the poll locked the work item and then needed the session row for the sessions token it mints, while a delete or a `user.interrupt` holds the session row and then needs the item. A session waiting on its worker is idle, so a delete is allowed while its item can still be polled, and Postgres broke the lock cycle by aborting either side: a 500 from the poll, the delete or the interrupt. The poll no longer waits for the session row: while another transaction holds it, the poll returns no work and the next poll hands the item out unchanged.
