- **A worker's poll no longer deadlocks against a session delete or interrupt** ([#643](https://github.com/OpenSDLC-Dev/managed-agent-platform/issues/643)) — A worker's poll racing the delete of, or a `user.interrupt` to, a `self_hosted` session with a memory store attached could fail one of the two with a 500. Migration 0043 drops the foreign key from `work_session_tokens` to `sessions`; a trigger on `sessions` deletes a session's tokens with it, whatever deletes the row, a replica still on the previous build included. The migration needs `work_session_tokens` and `sessions` exclusively, and waits at most 500ms for each, so during a rolling upgrade it gives way to live traffic rather than queueing every session read behind it or deadlocking with an old replica. Every migration run now retries a lock timeout or deadlock, up to five attempts over about 15 seconds, and each retry re-applies all pending migrations, since they share one transaction. A start whose attempts all fail exits with the error, and a later start applies the migration.
