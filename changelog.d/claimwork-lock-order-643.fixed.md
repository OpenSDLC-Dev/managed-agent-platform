- **A worker's poll no longer deadlocks against a session delete or interrupt** ([#643](https://github.com/OpenSDLC-Dev/managed-agent-platform/issues/643)) — For a `self_hosted` session with a memory store attached, the poll locked the work item and then needed the session row for the sessions token it mints, while a delete or a `user.interrupt` holds the session row and then needs the item. A session waiting on its worker is idle, so a delete is allowed while its item can still be polled, and Postgres broke the lock cycle by aborting either side: a 500 from the poll, the delete or the interrupt. The poll now takes the session row together with the item and waits for neither. While another transaction holds a session's row, the poll passes over that session's items and hands out the next item in the queue; a passed-over item goes out on a later poll unless the holder deleted or stopped it.
