- **A deployment echoes each resource's `mount_path` as it was sent** ([#849](https://github.com/OpenSDLC-Dev/managed-agent-platform/issues/849)) — As the reference was recorded doing, a deployment's file and repository resources now read back with the `mount_path` the request gave: `/uploads/report.csv` reads back as `/uploads/report.csv`, not `/mnt/session/uploads/report.csv`, and an omitted one reads back with no `mount_path` key. The resolved path is still stored and is what every fire mounts, so a rolling update or a rollback mounts the same paths. Create and update still refuse a path that cannot resolve, and two resources whose resolved paths collide or nest, such as `/uploads/x` beside `/x`; that refusal now names both spellings sent and what they resolve to. A deployment also refuses a `mount_path` spelling longer than 1024 bytes, since it stores and echoes it. Deployments stored before the upgrade keep echoing their resolved paths. Finish a rollout from a release before #848 before editing deployments: an older pod saving a new pod's echoed `/uploads/x` stores its own doubled resolution.
