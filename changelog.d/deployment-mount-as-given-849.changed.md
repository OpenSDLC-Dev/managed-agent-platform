- **A deployment echoes each resource's `mount_path` as it was sent, and resolves it when it fires** ([#849](https://github.com/OpenSDLC-Dev/managed-agent-platform/issues/849)) — As the reference was recorded doing, deployment create and update now store a file's or repository's `mount_path` as given: `/uploads/report.csv` reads back as `/uploads/report.csv`, not `/mnt/session/uploads/report.csv`, and an omitted one reads back with no `mount_path` key. A path that cannot resolve is still refused at create or update, in the same words. The session a fire or manual run creates mounts the resolved path, as before. Resources are still checked against each other on their resolved paths, so `/uploads/x` beside `/x` is still refused at create or update. Deployments stored before the upgrade keep their resolved paths, in the echo and at the fire.
