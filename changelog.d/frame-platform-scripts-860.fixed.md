- **The platform's sandbox scripts read only what they print, so an image whose startup prints no longer breaks them or corrupts their answers** ([#860](https://github.com/OpenSDLC-Dev/managed-agent-platform/issues/860)) — On an image whose `ENV BASH_ENV` file printed, the Kubernetes backend failed every exec (the banner was read as the exit code) and silently corrupted every file read, returning the banner's bytes as the file's — which `edit` could write back — or, behind an `EXIT` trap that printed, failed every read as short; a memory store never landed (its empty directory's listing read as files), the package-install probe's answer went unrecognized, and a refused write could carry the banner as its reason. The scripts whose answers the platform parses — the outputs harvest's listing, the memory sync's tree hash, the package-install probe, the refused-write reasons, and on Kubernetes the file reads, exit record, liveness probe and checkpoint probe — now print them between a begin and an end line carrying a nonce of their own, as `glob` and `grep` already did, and only what lies between is read, under an `errexit` startup too; a bulk write's failure report no longer loses the member it names to a banner. A library an `ENV LD_PRELOAD` names that prints from a script's child lands inside those lines, which the [image contract](docs/self-hosted-security.md) forbids.
