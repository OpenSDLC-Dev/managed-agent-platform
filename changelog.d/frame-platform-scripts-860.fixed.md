- **The platform's own sandbox scripts read only what they print, so an image whose startup prints no longer breaks them** ([#860](https://github.com/OpenSDLC-Dev/managed-agent-platform/issues/860)) — On an image whose `ENV BASH_ENV` file printed, on either stream or from an `EXIT` trap, the Kubernetes backend failed every exec (the banner was read as the exit code) and every file read, a memory store never landed (its empty directory's listing read as files), the package-install probe's answer went unrecognized, and a refused write could carry the banner as its reason. Every platform script whose output is read now prints its answer between a begin and an end line carrying a nonce of its own, as `glob` and `grep` already did, and only what lies between them is read: the outputs harvest's listing, the memory sync's tree hash, the package-install probe, the refused-write reasons, and on Kubernetes the file reads, exit record, liveness probe and checkpoint probe. A library an `ENV LD_PRELOAD` names that prints from a script's child lands inside those lines, which no frame keeps out; the [image contract](docs/self-hosted-security.md) forbids it.
