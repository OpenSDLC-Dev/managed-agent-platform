- **The platform's sandbox scripts read only what they print, and run as written whatever an image's startup file sets** ([#860](https://github.com/OpenSDLC-Dev/managed-agent-platform/issues/860)) — On an image whose `ENV BASH_ENV` file printed, the Kubernetes backend failed every exec (the banner was read as the exit code) and silently corrupted every file read, returning the banner's bytes as the file's — which `edit` could write back — or failed every read behind an `EXIT` trap that printed; a memory store never landed, the package-install probe's answer went unrecognized, and a refused write could carry the banner as its reason. The scripts whose answers the platform parses now print them between begin and end lines carrying a nonce of their own, as `glob` and `grep` already did, and only what lies between is read; a bulk write's report comes from newline-led marker lines only a startup printing those exact lines could displace. A file that sets `-e` no longer stops a non-root Docker sandbox's bulk writes at their first `chmod`, has Kubernetes report every failing command as killed (137), or spares a runaway its deadline's kill: every platform script turns errexit off as it starts, and the exec wrappers guard each step. One printing past the 1 MiB output cap gets tool errors naming the image, not a retry loop. A library an `ENV LD_PRELOAD` names printing from a script's child lands inside those lines; the [image contract](docs/self-hosted-security.md) forbids it.
